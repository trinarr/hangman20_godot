# Награды: patch 06

Патч применяется к проекту, на который уже наложены patch 01–05,
последний — `hangman-2.0_patch_05_english_database.patch`.
Исходный пользовательский `hangman-2.patch` отдельно накладывать не нужно:
его изменения уже включены и исправлены.

```bash
git apply --check hangman-2.0_patch_06_rewards.patch
git apply hangman-2.0_patch_06_rewards.patch
```

Команды выполняются из корня проекта, рядом с `project.godot`.
Если файл патча лежит в другом каталоге, укажите путь к нему.

## Сохранённые правила пользовательского патча

- Успешный этап виселицы даёт 10 монет; этап встроенной викторины — 15.
- Викторина предлагает удвоить свою награду за рекламу.
- После последнего этапа многоэтапного уровня открывается отдельный сундук:
  25 + 10 монет за каждый выигранный этап. Для сложного уровня: 50 + 20.
  Награда выдаётся и при поражении на последнем этапе, даже при нуле побед.
- Монеты сундука начисляются при открытии; реклама добавляет ещё такую же сумму.
  Затем отдельный экран выдаёт по одной звезде за каждый выигранный этап.
- Одноэтапный уровень имеет только обычную награду этапа с предложением x2.
  Сундука и дополнительного экрана звёзд нет; звезда за победу выдаётся при выходе
  из предложения. Дополнительные звёзды за оставшиеся попытки/быстрый ответ
  работают как прежде.
- Общая адаптивная сложность продолжает меняться после каждого этапа.
  Изменения баз слов из patch 05 и ресурсы El Tigre сохранены.

## Исправления

Начисления отделены от анимации. Снимок сундука хранит `claimed`,
`double_resolved` и `double_claimed` до перехода к звёздам. Переход заменяет
снимок сундука снимком звёзд одним сохранением. Перезапуск после открытия
сундука или получения рекламного бонуса больше не теряет следующий экран.

У звезды одноэтапного уровня есть сохранённый флаг получения.
Повторный результат этапа не сбрасывает флаги уже выданной награды.
Рекламный бонус сундука также имеет постоянную защиту от повторного получения;
сумма фактического начисления учитывает предел баланса.
Кнопка X на результате сохраняет незавершённую выдачу наград для продолжения.
Запоздавший таймер закрытия предыдущей рекламы не закрывает новое предложение.

Убраны неиспользуемые варианты подарка, подписи, лишние ветки панели
и повторный подсчёт монет по всем этапам. На экранах награды за уровень
не создаются невидимые плитки цепочки и отдельный SubViewport персонажа.
Текстуры сундука загружаются через ResourceLoader и повторно используются.
Материал вспышки общий; после анимации слой вспышки скрыт.

Шейдер вынесен в `shaders/reward_chest_flash.gdshader`: меняет только RGB,
сохраняя уже рассчитанный Godot альфа-канал. Нет дополнительной выборки текстуры
и двойного умножения её прозрачности. Поведение COLOR сверено с
[документацией Godot](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html#color-and-texture).

## Проверки

- Godot 4.6.1, headless: 53 проверки сложности и 162 проверки наград/геометрии текста.
- Сохранение и загрузка между результатом этапа, сундуком, рекламой и звёздами;
  повторные результаты и рекламные сигналы, оба порядка rewarded/closed,
  одноэтапный уровень, проигрыш последнего этапа, ноль побед, лимит баланса.
- Английский интерфейс с русскими словами; геометрия текстовых слоёв при
  размерах 690×1536 и 960×1600.
- `verify_save_integrity.py` и `verify_word_catalog.py`.
- Экспорт PCK и загрузка обоих сундуков и шейдера из него; редакторские каталоги
  и тестовые файлы исключены из пакета.
- Применение патча к отдельной копии точного состояния patch 05 с побайтовым
  сравнением результата.

Тесты пишут сохранения: запускайте с отдельным каталогом данных.

```bash
XDG_DATA_HOME=/tmp/hangman-reward-tests godot --headless --path . res://tools/tests/rewards.tscn
XDG_DATA_HOME=/tmp/hangman-difficulty-tests godot --headless --path . res://tools/tests/stage_difficulty.tscn
python3 tools/verify_save_integrity.py
python3 tools/verify_word_catalog.py
```

Полный APK, реальная реклама и GPU-анимация на Android не проверялись.
Headless-проверки подтверждают логику и геометрию, но не заменяют визуальную
проверку на телефоне. В тестовом окружении остаётся предупреждение ObjectDB
при завершении, которое встречается и в исходной проверке patch 05.

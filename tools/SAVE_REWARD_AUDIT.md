# Аудит сохранений, наград и продолжения игры — 24.09.2026

База патча: исходный архив `hangman-2.0(8).zip`. Изменения из более ранних
архивов не переносились автоматически. Патч применяется из корня проекта:

```bash
git apply --check hangman20_save_reward_audit_v2.patch
git apply hangman20_save_reward_audit_v2.patch
```

## Исправления

| Проблема | Изменение |
| --- | --- |
| Прерывание замены основного сейва оставляет полный `.tmp`, но загрузчик выбирает старый backup | При отсутствии или несовместимости основного сейва сначала проверяется временный файл текущего формата, затем backup. Валидный основной сейв остаётся приоритетным. |
| JSON с неподходящей старой версией мешает восстановиться из корректного backup | Загрузчик проверяет резервные файлы и не копирует несовместимый основной файл поверх backup при восстановлении. Защита сейва из будущей версии сохранена. |
| Поздняя награда x2 после смены языка начисляет монеты, но не закрывает предложение в прежней кампании | По идентификатору цели обновляются и флаги неактивной кампании. Баланс, флаги и удаление повторных запросов сохраняются вместе; при ошибке записи восстанавливаются в памяти. |
| Быстрый выход с результата оставляет отложенные вызовы с уже удалёнными узлами | Перед запуском подпрыгивания проверяются поколение экрана и ссылки на узлы. Анимация бумажки привязана к её узлу и прекращается при его удалении. |

Формат сейва остаётся `2`. Награды, цены и правила завершения уровней не менялись.

## Поведение после «Продолжить»

- Слово, открытые буквы, ошибки, попытки и использованные подсказки берутся
  из сохранённого состояния. Восстановление само по себе не тратит сердце.
- Ожидание последнего шанса сохраняется. Уже зафиксированное поражение
  не списывает второе сердце при продолжении.
- Викторина восстанавливает вопрос, порядок ответов и использованное 50/50.
  Уже начисленные звёзды за скорость не начисляются повторно.
- Уже показанное крупное предложение награды может не открываться повторно:
  существующая логика завершает базовую выдачу и переходит дальше по цепочке
  либо на главный экран. Это не означает потерю базовой награды.
- Рекламные запросы не удаляются по возрасту: поздний подтверждённый ответ
  должен оставаться обрабатываемым. Повторный ответ по оплаченной цели
  не создаёт новую выдачу.

## Проверки

Godot 4.6.1, Linux, headless, отдельные временные каталоги `user://`:

| Набор | Успешные проверки |
| --- | ---: |
| `rewards` | 262 |
| `runtime_optimizations` | 49 |
| `save_recovery` | 49 |
| `resume_flow` | 18 |

`save_recovery` включает запуск отдельных процессов Godot: подготовка
прерванной записи, автоматическое восстановление autoload при новом запуске,
позднее подтверждение рекламы и ещё один запуск после выплаты. Также проверены
откат операции при отказе сохранения и защита от повторной выплаты в RU/EN.

`resume_flow` проходит через реальные маршруты главного экрана и «Продолжить».
В headless тестах эмулируется только сигнал завершения кадра, отсутствующий
у dummy renderer. Это не проверка качества анимации на устройстве.
Старые тестовые стенды адаптированы к асинхронным переходам актуального проекта.

```bash
python3 tools/run_reward_tests.py --godot /path/to/godot --suite rewards
python3 tools/run_reward_tests.py --godot /path/to/godot --suite runtime_optimizations
python3 tools/run_reward_tests.py --godot /path/to/godot --suite save_recovery
python3 tools/run_reward_tests.py --godot /path/to/godot --suite resume_flow
python3 tools/verify_save_integrity.py
```

Все 378 проверок прошли без `SCRIPT ERROR`/`ERROR`. При завершении некоторых
UI-стендов Godot сообщает `ObjectDB instances leaked at exit`; этот патч
не устраняет все предупреждения о времени жизни объектов в проекте.

## Ограничения и следующие доработки

1. При нехватке места или отказе файловой системы некоторые существующие
   операции обычных наград/подсказок не обрабатывают `false` от `save_game()`.
   Следующий шаг — транзакционная обработка таких операций и понятное сообщение
   игроку при невозможности сохранить прогресс. Проверенный откат x2 не означает,
   что все изменения экономики уже имеют такую обработку.
2. Запрос рекламы не доказывает завершённый просмотр. Если процесс убит до
   подтверждения от SDK, одного локального запроса недостаточно для выплаты.
   Нужна отдельная проверка поведения нативного SDK на Android; здесь callback
   имитируется. Автовыдача всех незавершённых запросов не добавлена.
3. Таймер бонуса за скорость викторины запускается заново после появления
   восстановленного вопроса. Это позволяет получить новое окно быстрого ответа
   через перезапуск. Если это нежелательно, нужно сохранять израсходованное время
   либо исключать бонус при восстановлении — это отдельное изменение правил.
4. Снимки для «Продолжить» предусмотрены для одиночной кампании. Раунд двух
   игроков не имеет аналогичного долговременного восстановления; если оно нужно,
   следует добавить отдельный тип снимка с учётом скрытого загаданного слова.

APK, реальная реклама и принудительное завершение Android-процесса на устройстве
в эту проверку не входили. Применимость патча проверяется отдельно на исходных
байтах актуального архива.

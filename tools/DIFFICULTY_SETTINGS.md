# Настройка адаптивной сложности

Редактируется `data/game_design_config.json`, раздел `difficulty`.
Патч применяется поверх `hangman_adaptation_slowdown_50.patch` и заменяет
его отдельный коэффициент `adaptation_speed` обычными таблицами.
Сохранённая глобальная сложность не сбрасывается. Вводный режим новых тем
настраивается отдельно, как описано ниже.

## Три существующие таблицы

- `win_steps`: базовая прибавка за победу по `below_difficulty`.
- `win_streak_multipliers`: диапазоны `below_difficulty`, внутри каждого
  массив `streaks` с `from_wins`, `to_wins`, `multiplier`.
- `loss_steps`: диапазоны `below_difficulty`, внутри каждого массив `streaks`
  с `from_losses`, `to_losses`, `decrease`.

Победа: `increase × multiplier`. Поражение: `−decrease`.
Других множителей замедления нет. Серия включает текущий результат;
поражение сбрасывает серию побед и наоборот.

Выбирается первая строка, где текущая сложность **до результата** строго меньше
`below_difficulty`. При сложности ровно 0,50 используется следующий диапазон.
Строки должны идти по возрастанию; последняя граница должна превышать
`difficulty.maximum`. Значение 1,01 покрывает всю шкалу 0–1.
Границы трёх таблиц можно задавать независимо.

`from_wins`/`from_losses` и `to_wins`/`to_losses` включительны.
Ноль у верхней границы серии означает отсутствие ограничения.
Серии внутри каждого диапазона должны покрывать 1…∞ без пропусков/пересечений.
Шаги и множители могут быть нулевыми, но не отрицательными.

Пример диапазона множителей побед:

```json
{"below_difficulty": 0.7, "streaks": [
  {"from_wins": 1, "to_wins": 2, "multiplier": 1.0},
  {"from_wins": 3, "to_wins": 5, "multiplier": 1.10},
  {"from_wins": 6, "to_wins": 0, "multiplier": 1.15}
]}
```

Этот пример показывает возможность редактирования. В поставленной конфигурации
исходные множители 1,0 / 1,15 / 1,25 сохранены во всех диапазонах.

## Начальные значения патча

| Сложность | База победы | Поражение 1 / 2 / 3+ подряд |
| --- | ---: | --- |
| < 0,30 | 0,0100 | 0,012 / 0,020 / 0,030 |
| 0,30–<0,50 | 0,0060 | 0,009 / 0,015 / 0,0225 |
| 0,50–<0,70 | 0,0036 | 0,0072 / 0,012 / 0,018 |
| ≥ 0,70 | 0,0020 | 0,006 / 0,010 / 0,015 |

Это 100%, 75%, 60%, 50% исходных шагов соответствующих диапазонов.
Переходы теперь ступенчатые. Для более мелких переходов добавляйте диапазоны.
Изменение таблиц не пересчитывает прошлые результаты; применяется со следующего
нового результата. Повторная обработка завершённого этапа не меняет сложность.

Плоские старые форматы `win_streak_multipliers` и `loss_steps` также поддерживаются:
они действуют при любой сложности. Нельзя смешивать плоские строки и диапазоны
внутри одной таблицы.

## Проверка после редактирования

```bash
python3 tools/verify_game_design_config.py --difficulty-only
```

Проверяются порядок границ, покрытие максимума, непрерывность серий,
неотрицательные значения и совместимость формата. Проверка не требует
конкретных темпов достижения сложности и позволяет свободно менять баланс.

Регрессии Godot: `tools/tests/adaptation_speed.gd` — 16 проверок, включая
границы, независимые множители, старый формат и защиту от повторного результата.
Запускать с отдельным `XDG_DATA_HOME` на Linux, поскольку проект загружает сейв
через autoload. На Godot 4.6.1 headless все проверки пройдены.


## Вводная сложность новых тем

Раздел `progression.theme_intro`:

```json
"theme_intro": {
  "catch_up_rate": 0.25,
  "completion_tolerance": 0.04
}
```

При первом подборе слова или вопроса в ещё не сыгранной нестартовой теме создаётся её вводная сложность
`T = difficulty.minimum` (сейчас 0,08). Это цель подбора, а не обязательная
сложность выбранного слова: база дискретна, продолжают действовать штрафы
за повторы и случайная добавка к оценке кандидата.

После каждого отгаданного слова или правильного ответа викторины этой темы:

`T = T + catch_up_rate × (G − T)`

`G` — глобальная сложность после обработки этой победы обычными таблицами.
Большой разрыв даёт большую прибавку; приближение замедляется по мере сближения.
Это пропорциональное подтягивание, а не буквальная формула рейтинга Эло.
`catch_up_rate` допустим в диапазоне (0; 1]: 0,25 закрывает четверть разрыва,
1 завершает подтягивание за одну победу.

При `G − T <= completion_tolerance` вводный режим заканчивается навсегда.
Допуск положительный и меньше полного диапазона сложности. Если из-за поражений
глобальная сложность опустилась ниже вводной, режим тоже завершается: тема
не остаётся сложнее глобальной. Последующий рост `G` не запускает ввод заново.
При неизменной глобальной сложности 0,86 настройки по умолчанию дают 11 побед суммарно в виселице и викторине
до завершения ввода с начальных 0,08. При движущейся глобальной сложности
число побед меняется; фиксированного количества вводных этапов нет.

Пока ввод активен, слова и вопросы подбираются относительно общей `T` без смещения по позиции
в цепочке и без бонусной прибавки. После завершения работают прежние правила
глобального подбора, включая эти смещения. Победы в виселице и викторине
продвигают одну общую вводную сложность темы. Поражения и выходы не повышают `T`.
Повторно доставленный результат не засчитывается второй раз.

Состояние хранится в сейве отдельно для языка и стабильного ID темы:
`single_player[language].theme_intro[theme_id]`. Смена темы, перезапуск,
«Продолжить» и сброс цепочки его не обнуляют. Уже назначенное слово или вопрос
сохраняется; новая цель применяется к следующим ещё не назначенным этапам.
В старых сейвах темы с историей показанных/отгаданных слов или показанных
вопросов викторины считаются прошедшими
ввод. Разблокированные, но ещё не сыгранные темы начинают с минимума, как и
темы, открытые позднее.

Исключение: стартовые темы из `progression.theme_unlocks.initial_theme_ids`
(сейчас ID 1, 9, 2) сразу используют глобальный подбор со стандартными
смещениями цепочки. Вводный режим для них не запускается даже на новом профиле.
Если предыдущая сборка уже создала им вводное состояние, оно помечается
завершённым при следующем обращении. Уже назначенное слово не заменяется;
исправление действует на последующий подбор.

Проверка `--difficulty-only` также проверяет настройки ввода.
Регрессии: `tools/tests/theme_intro.gd` — подбор, результаты слов и викторин,
миграция старых сейвов, сохранение и загрузка, завершение и защита от дублей.
Запускать с отдельным `XDG_DATA_HOME`, как и остальные тесты сейвов.


## Отладка на экране цепочки

Только в debug-сборках на экране результата этапа появляется тостер на 8 секунд:
глобальная сложность после результата, активность и значение ввода темы,
фактическое изменение глобальной сложности и текущая серия побед/поражений.
При достижении предела дельта показывает фактический сдвиг, а не номинальный шаг.
Снимок сохраняется вместе с результатом и восстанавливается через «Продолжить».
Для старых результатов без снимка показывается текущее состояние; историческая
дельта обозначается «нет данных».

В debug-сборках последний этап ждёт кнопку «Продолжить», прежде чем показать
главную награду уровня. В release-сборках тостер отсутствует и прежний
автоматический переход сохранён. Проверка: `tools/tests/debug_chain.gd`.

# Настройка сложности

Значения редактируются в `data/game_design_config.json`; реализация — `scripts/core/game_design_config.gd`. Таблицы ниже описаны по назначению, без копии текущих чисел баланса.

- `difficulty.win_steps`: базовая прибавка за победу по границам `below_difficulty`.
- `difficulty.win_streak_multipliers`: множитель по текущей серии побед и диапазону сложности.
- `difficulty.loss_steps`: уменьшение сложности по серии поражений и диапазону.

Выбирается первая строка, где сложность до результата строго меньше границы. Границы идут по возрастанию и покрывают допустимый диапазон. Диапазоны серий включительны; нулевая верхняя граница серии означает отсутствие ограничения. Победа сбрасывает серию поражений и наоборот. Не переносите числовые значения из старых отчётов.

## Ввод новой темы

`progression.theme_intro` управляет подтягиванием новой темы к глобальной сложности. Пока ввод активен, слово и вопрос используют общую цель темы. После победы она приближается к глобальной цели согласно `catch_up_rate`; `completion_tolerance` задаёт завершение. Это пропорциональное подтягивание, а не фиксированное количество вводных этапов.

Состояние темы хранится отдельно для языка и стабильного ID темы. Смена темы и продолжение игры не сбрасывают его. Уже назначенное слово или вопрос сохраняется; изменённая цель применяется к следующим назначениям. Начальные темы из `progression.theme_unlocks.initial_theme_ids` используют глобальный подбор без ввода. Детали миграций и исключений проверяйте в `GameState` и тестах.

## Проверки

```powershell
python tools/verify_game_design_config.py
python tools/run_content_tests.py --godot 'C:/path/to/Godot.exe' --suite adaptation_speed
python tools/run_content_tests.py --godot 'C:/path/to/Godot.exe' --suite theme_intro
```

Запускатели изолируют сохранения; подробности в [TESTS.md](TESTS.md). Механические тесты могут использовать фиксированные входные данные, поэтому их ожидаемые числа не являются текущим игровым балансом.

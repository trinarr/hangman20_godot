# Запуск тестов на Windows и Linux

Сценарий `network_retries` проверяет сохранение подтверждённых звёзд, перезапуск и смену аккаунта, новый рекорд во время запроса, ошибочное подтверждение, рост/предел/сброс задержек, общий отказ авторизации и независимость API. Используются mock-транспорт и управляемые монотонные часы, без сетевых запросов и реального ожидания интервалов.

Игра предназначена для Android. Эти команды проверяют её логику на настольном Godot и не заменяют проверку сборки на телефоне.

После импорта ресурсов выбранной версией Godot, из корня проекта:

```powershell
python tools/run_content_tests.py --godot 'C:/path/to/Godot.exe'
python tools/run_reward_tests.py --godot 'C:/path/to/Godot.exe' --suite rewards
python tools/run_reward_tests.py --godot 'C:/path/to/Godot.exe' --suite save_recovery
python tools/run_reward_tests.py --godot 'C:/path/to/Godot.exe' --suite resume_flow
python tools/run_reward_tests.py --godot 'C:/path/to/Godot.exe' --suite runtime_optimizations
python tools/verify_game_design_config.py
python tools/verify_optimization.py
python -m unittest discover -s tools/tests -p 'test_*.py'
```

На Linux команды те же, с Linux-бинарником в `--godot`. Отдельный контентный сценарий выбирается через `--suite <name>`; список смотри в `--help`. Перед запуском ресурсы должны быть импортированы, например `Godot.exe --headless --editor --import --path .`.

`godot_test_runner.py` создаёт временный профиль, задаёт APPDATA/LOCALAPPDATA только дочернему процессу на Windows либо XDG-каталоги на Linux. До запуска игровых autoload отдельный минимальный проект с теми же настройками `[application]` проверяет реальный `OS.get_user_data_dir()`. Путь вне временного профиля, ошибка движка или отсутствие отчёта прерывают запуск. Локальный `override.cfg` также блокирует запуск, поскольку он может изменить проверенные настройки. Исходный проект и настройки Android не меняются. Механизм Windows соответствует [реализации путей Godot](https://github.com/godotengine/godot/blob/master/platform/windows/os_windows.cpp) и дополнительно проверяется самим используемым бинарником.

Все фазы `save_recovery` используют один профиль для проверки перезапусков; разные контентные сценарии получают разные профили. Поддерживающая флаг сеть Supabase отключена. stdout и файл журнала Godot проверяются вместе, включая GUI-бинарники Windows без доступного stdout. Exit code 0 без ожидаемого итогового отчёта не считается успехом. Предупреждения ObjectDB остаются видимыми.

`rewards` разделяет награды уровня, награды этапа с рекламными receipt и жизненный цикл представления. Суммы обычных и сложных уровней рассчитываются из `economy.rewards` и результатов фикстуры: слово даёт звёзды, викторина — монеты, звёздный этап не предлагает монетное ×2. Перед рекламными callback проверяется наличие уже начисленной положительной награды. Сценарии охватывают оба порядка rewarded/closed, повторные и поздние сигналы, прежнюю цель при новой награде, отмену, неизвестный receipt, перезапуск и предел баланса. В debug-сборке тест проходит штатный ручной шаг «Продолжить» перед итоговой наградой.

`resume_flow` проверяет защиту сердец на первых двух уровнях, а после порога из `progression.guided_onboarding.required_start_level` — сохранение последнего шанса до решения, списание ровно одного сердца при поражении и отсутствие повторного списания после загрузки. Геометрию дополнительного нижнего отступа попапа проверяет `portrait_popup_component`; `verify_save_integrity.py` дополнительно проверяет его подключение в попапе последнего шанса, бесплатную кнопку и правила закрытия.

`level_reward_navigation` проверяет выход с главной награды на уровне `tournament.unlock_completed_levels` и соседних уровнях: RU/EN, 960×1600 и 690×1536, с рекламной кнопкой и без неё, победу/поражение последнего этапа и нулевые сердца. На уровне открытия турнира «Нет, спасибо»/«Продолжить» возвращают на главный экран с одним стартовым попапом; соседи открывают следующую тему. Также проверяется настройка открытия на одноэтапном уровне без отдельной главной награды. Проверяются повторное нажатие, оба порядка рекламных сигналов, ошибка показа рекламы, восстановление показанной награды, отсутствие повторного вступления, устаревший callback, ожидание модального окна и приоритет неполученного турнирного приза. Для GPU-снимков задайте существующий `HANGMAN_UI_CAPTURE_DIR`; запуск выполняйте в `isolated_environment`.

Чтение/запись текстовых файлов инструментами использует явную UTF-8. Установка `PYTHONUTF8=1` больше не требуется для корректного чтения каталогов.

Для регрессии изоляции с настоящим движком:

```powershell
$env:HANGMAN_TEST_GODOT = 'C:/path/to/Godot.exe'
python -m unittest discover -s tools/tests -p test_project_tools.py
```

Проверяется отказ при небезопасном пути, сохранение между двумя процессами, чистота следующего профиля и неизменность окружения родителя. Без `HANGMAN_TEST_GODOT` тест реального движка пропускается; остальные регрессии работают без Godot.

Для GPU-проверки редактора персонажа запускайте `tools/tests/profile_ui.tscn` без `--headless` в окружении `isolated_environment`. `HANGMAN_PROFILE_PREVIEW_LANGUAGE=ru` / `en` выбирает язык, `HANGMAN_PROFILE_PREVIEW_SIZE=960x1600` / `690x1536` задаёт фактический размер окна, включая минимальный размер на Windows. `HANGMAN_PROFILE_PREVIEW_DIR` указывает существующий каталог для PNG редактора и профиля. Проверяйте бумажный низ без синей панели, отступ кнопки закрытия и повторное открытие/закрытие.

`profile_ui` также проверяет фильтрацию ника при изменении поля: удаление недопустимых символов и краевых пробелов, сведение повторных пробелов к одному, ограничение до 18 разрешённых символов после вставки, положение курсора в середине текста и синхронизацию видимого/нативного поля. При наборе второго слова разделитель появляется только вместе с его первой буквой/цифрой; навигация курсором отменяет ожидающий разделитель. Сценарий с имитацией активной IME проверяет отложенную очистку нативного буфера после композиции и запрет сохранения до её завершения; реальную Android-клавиатуру проверяйте на устройстве.

`profile_ui` проверяет доступность «Сохранить» по отличиям всего черновика от текущего профиля: ник, персонаж и рамка. Проверяются открытие без изменений, отдельное изменение каждого поля и возврат к сохранённому значению, автоматический серверный суффикс и внешнее обновление профиля при открытом редакторе.

Оплату ника проверяют `save_recovery` (миграция 6→7, бесплатное право, повторная оплата, отказ записи, недостаточный баланс, повторный вызов и перезагрузка) и `profile_ui` (зелёная бесплатная кнопка, общая строка цены с монетой, красная цена, живой счётчик баланса и возврат из магазина к тому же черновику). При GPU-проверке сверяйте бесплатный и платный варианты кнопки в обоих языках и размерах.

В `profile_ui` также проверяются горизонтальное центрирование счётчика монет в фактическом viewport и подпись «Сохранить» у неизменённого профиля: при открытии и после возврата ника, персонажа или рамки к сохранённым значениям. «Бесплатно» появляется при наличии бесплатных изменений.

`portrait_popup_component` проверяет выбор счётчика монет нижнего слоя для магазина: геометрию ближайшего видимого счётчика, скрытые/закрывающиеся слои, исключение собственного и более высокого слоёв, очистку после удаления и штатную позицию при отсутствии источника. `profile_ui` проверяет совпадение позиций счётчиков редактора и магазина, сохранение геометрии основного HUD и повторное открытие магазина. На GPU сравнивайте снимки редактора и магазина в RU/EN при 960×1600 и 690×1536.

## Фоновые загрузки ресурсов

`python tools/run_content_tests.py --godot 'C:/path/to/Godot.exe' --suite resource_loading` проверяет автоматический сбор невостребованных результатов, повторный запрос, отсутствие ожидания в кадровом опросе, ошибки/отказ/невалидный статус, отключение подписок, синхронный fallback иконки и реальные загрузки обоих каталогов. Для обоих персонажей проверяются уход со страницы до завершения загрузки, готовность терминальной позы и ограничения окна/предзагрузки при переходе по состояниям. Mock-загрузчик позволяет проверить незавершённые и ошибочные задачи без порчи файлов ресурсов.

`--suite resource_loading_shutdown` завершает процесс сразу после запуска предзагрузки обоих каталогов и поз: сбор выполняет штатная очередь при выходе дерева. В обоих сценариях предупреждение ObjectDB считается провалом запуска. Дополнительно проверяйте `portrait_stage_reward`, `portrait_round_result`, `tournament_ui` и `run_reward_tests.py --suite runtime_optimizations`; тесты не должны вручную очищать очередь перед выходом.

## Профиль игрока

`tournament_start_popup` проверяет старт из кнопки главного экрана, повторные нажатия, сохранённый отсчёт до подтверждения, возврат к рейтингу при активном турнире, принудительный выход на главный при завершении турнира на обеих вкладках с призом/без приза и защитой от устаревшего callback, запрет замены неполученного приза, переход с полученной награды к следующему турниру и отказ при недоступном сохранении. Проверяются крестик и Back, сохранение отсчёта при повторном открытии, секундное обновление таймера, закрытие стартового попапа при нуле с сохранением неполученной награды, цветные часы слева от цифр с равными левым/верхним/нижним отступами и одна большая стрелка: плавные четверти оборота, небольшой перелёт, возврат и неподвижная пауза на каждой отсечке; проверяются все четыре четверти, промежуточные углы и длинный кадр, уменьшение плашки таймера на 15% и центрирование его плашки на верхней границе блока, уменьшение высоты блока на 30%, зазор кубка под таймером, отдельные PNG кубка снизу и пьедестала без статических подарков и горстей монет, движение монетного дождя за кубком, свечение между занавесом и наградами, маска занавеса, игровая звезда внутри локализованных инструкций, оранжевая кнопка, компоновка и движение блеска кубка в RU/EN при 960×1600 и 690×1536. GPU-запуск в изолированном профиле при `HANGMAN_UI_CAPTURE_DIR` сохраняет четыре PNG; окно скрывайте средствами ОС. `tournament` дополнительно проверяет автостарт от игровых звёзд, первое начисление внутри save batch, перезапуск, порог разблокировки и защиту неполученной награды. Административные звёзды автостарт не вызывают.

`startup_last_chance` проверяет автоматическое восстановление первого этапа после последней ошибки: попап «Продолжить?» остаётся после перехода с главного экрана, повторный запуск сохраняет ровно один попап и состояние партии, бесплатное продолжение возвращает ввод букв. Проверяется настоящий клик по клавиатуре, RU/EN, размеры 960×1600 и 690×1536, неиспользованный/открытый комментарий. Для GPU-прогона сцены в изолированном профиле `HANGMAN_UI_CAPTURE_DIR` сохраняет кадры после восстановления; окно запускайте скрыто.

`tournament_finish_popup` проверяет автоматический показ на главном экране только при неполученной призовой награде, окончание турнира на открытом главном экране, повторный вход, отсутствие закрытия по Back/затемнению, три итоговые строки с выделением игрока, компактный блок монет со счётчиком, уменьшенный сундук, ошибку получения через стандартный верхний тостер над попапом без перехвата ввода, повторный показ и автоматическое скрытие тостера, повторное нажатие и отсутствие повторной выплаты. Проверяет сундук первого места и монеты второго/третьего, RU/EN при 960×1600 и 690×1536. Дополнительно проверяются перелёт награды из фактических границ попапа в центр, паттерн всех тем, локализованные заголовки места в цвете медали, промежуточная/конечная прозрачность заголовка, полёт монет и прокрутка HUD, открытие сундука с конфетти, уход во время перелёта/открытия/начисления без повторной выплаты. GPU-запуск той же сцены в изолированном профиле сохраняет PNG попапа, ошибки, перелёта, начисления и готовой награды при заданном `HANGMAN_UI_CAPTURE_DIR`; окно скрывайте средствами ОС, `HANGMAN_TEST_HIDE_WINDOW=1` включает принудительную отрисовку скрытого окна. Дополнительная регрессия награды проверяет отмену тоста после успешной повторной попытки, исключение исходной награды/суммы/HUD/тоста из снимка, завершение затухания до прилёта в центр, английские заголовки 1ST PLACE/2ND PLACE/3RD PLACE и размещение суммы под подарком по контракту главной награды уровня. Матрица награды включает также 1080×1920. Headless подтверждает только логику и геометрию.

`tournament` также проверяет минимальную задержку начислений ботам: нулевые звёзды до порога, допустимые времена всех событий, точную границу, первое начисление и сохранение расписания после перезапуска. Проверка использует задержку из баланса и альтернативное значение.

Серверная выборка турнира: `node tools/tests/tournament_profiles_sql.cjs` с доступным `@electric-sql/pglite` (при необходимости задайте `NODE_PATH`) проверяет только БД в памяти: миграцию 018, dev/prod, выбор за пределами топ-100, исключение своего игрока, короткую/пустую выборку с обходом кольца, публичные поля, права, индекс и повторное применение. Текущий клиент использует кеш глобального рейтинга и не вызывает этот RPC; историческую серверную схему проверяет SQL-тест в памяти.

`tournament` проверяет независимые настройки `tournament.duration_seconds` и `tournament.debug_duration_seconds`, выбор обоих режимов, сохранение дедлайна и расписания при смене сборки, включая прежний восьмичасовой турнир. `tournament`, `home_tournament` и `tournament_start_popup` используют длительность соответствующего режима сборки: проверяют начальный отсчёт, промежуточное время внутри турнира и дедлайн без фиксированных часов. `tournament_start_popup` проверяет формат часов без обрезки по границе суток.

`tournament` проверяет минимальное число фейков и пул профилей при отсутствии реальных участников, частичном заполнении и избытке профилей, языковое распределение фейков, исключение дублей ID/собственного игрока, копирование внешности без глобальных звёзд, новый seed, сохранение выбранных девяти профилей и миграцию турнира 1→2. `leaderboard` проверяет получение профилей из обоих кешей, приоритет текущего языка, исключение собственного ID и восстановление кеша после перезапуска. `save_recovery` проверяет переход общего сохранения 5→6.

`tournament_ui` проверяет обычные строки турнира в RU/EN при 960×1600, 690×1536 и 1080×1920, выделение игрока, профильные аватары и общие портретные текстуры с глобальным рейтингом. Дополнительно проверяются общий прокручиваемый список всех мест, стандартные медали в строках 1–3, награды по балансу справа от ника и слева от счётчика звёзд, отсутствие пересечений. Проверяется отсутствие старых кнопок запуска/получения/следующего турнира и демонстрационных строк без сохранённого состава. Получение через отдельный попап главного экрана проверяется для всех трёх призовых мест: открытие подарка/монетного экрана кампании, сохранённая выплата до анимации, запрет повторного начисления, переход к стартовому попапу следующего турнира и уход во время открытия подарка. Для визуальной проверки запускайте ту же сцену с GPU в окружении, проверенном `isolated_environment`; при заданном `HANGMAN_UI_CAPTURE_DIR` тест сохраняет PNG списка и трёх экранов наград в существующую папку. Headless проверяет геометрию, но не внешний вид.

Профиль игрока: `profile_bootstrap` проверяет первый запуск, сетевой запрет до обучения, серверный суффикс и защиту ручного имени; `profile_ui` — скрытие/появление аватара, сохранение из попапа и отказ записи; `save_recovery` — миграцию и восстановление; `leaderboard` — отправку и повторы. Проверки ника в `profile_bootstrap` и `profile_ui` охватывают русские/английские буквы с Ё/ё, цифры 0–9, одиночные обычные пробелы, длину 2–18 после обрезки краевых пробелов, запрет спецсимволов и невидимых символов, отказ сохранения недопустимого имени и сохранение обрезанного имени. Чтение прежних имён остаётся совместимым. Каталоги предложенных ников проверяет `python -m unittest discover -s tools/tests -p test_profile_nicknames.py`. Локальные SQL-тесты `tools/tests/player_profiles_sql.cjs` и `leaderboard_local_fillers_sql.cjs` запускаются через Node.js с доступным `@electric-sql/pglite` (при необходимости задайте `NODE_PATH`). Они создают временную БД в памяти и не подключаются к Supabase.

Обновление серверных фейковых ников: `python tools/build_leaderboard_filler_refresh.py --check` проверяет каталог v3 и миграцию 012; `tools/tests/leaderboard_filler_refresh_sql.cjs` через Node.js/PGlite проверяет обновление обоих окружений, повторное применение, ограничения длины, права, стили, языковые пропорции и сохранность ID/звёзд/реальных профилей. Тест использует только БД в памяти.

Внешность заполнителей: `python tools/build_leaderboard_filler_appearance.py --check` проверяет каталог v4 и миграцию 013. `tools/tests/composited_fade_render.tscn` запускается с GPU в окружении, проверенном `isolated_environment`, без `--headless`. Нулевая альфа сравнивается с независимым фоном: оставшийся вне группы текст не может стать ложным эталоном. Дополнительно проверяются пять последовательных шагов tween по пикселям, сообщения правильного ответа и награда в RU/EN, одинаковый Z всех текстовых/иконных слоёв, включая позднее созданные, завершение анимации и уход с экрана во время показа потери жизни. Точечный перенос прозрачности заголовка редактора и сумм наград проверяют `profile_ui`, `portrait_stage_reward` и `tournament_ui`. GPU-сценарий `composited_fade_render` также проверяет обёртку существующего `Label`: неизменность непрозрачного изображения и геометрии, промежуточную/нулевую альфу, повторное использование обёртки и сохранение привязок при изменении размера родителя. Для проверки адаптации обёртки добавляйте 1080×1920 к двум основным размерам.

Перенос составных блоков на `composited_fade.branch` проверяют `profile_ui`, `home_tournament`, `quiz_statistics`, `portrait_round_result`, `portrait_stage_reward`, `tournament_ui` и `portrait_visual_components`. GPU-сценарий дополнительно проверяет ветку с обрезаемой заливкой, независимую прозрачность родителя/текста, добавление текста в скрытую ветку, штатную кнопку ответа и `StageLongButton`: неизменность непрозрачного вида, полное скрытие фона/текста, восстановление после нажатия, единственный масштаб текста и Z после повторного `configure`. Для прогресса темы проверяется сохранение clip-иерархии и обновление обёрнутого счётчика. Динамическую иерархию проверяют `portrait_visual_components` и GPU-сценарий: поздние дети под изначально приглушённым контейнером, повторная пересборка, перенос обычных узлов и вложенных контроллеров между владельцами, прежний владелец после переноса, нулевая альфа и восстановление. `portrait_visual_components` также проверяет собственные множители `modulate`/`self_modulate`, перенос обёрнутого текста, повторный вход в дерево и начальное/промежуточное/остановленное состояние `SparkleFade.opacity`. Тесты выполняйте последовательно: проверки промежуточных анимационных состояний чувствительны к загрузке кадров.

GPU-сценарий `composited_fade_render` также проверяет повторное появление изначально скрытого крестика награды внутри родительской ветки, его промежуточную/нулевую прозрачность и полную анимацию открытия темы в RU/EN: видимое свечение, Z-слой итоговой надписи, скрытие всех пикселей (включая шейдерную тень полосы) и восстановление прозрачности при повторном показе блока. На Windows сверяйте фактический размер viewport: система может ограничить высоту окна; при необходимости задайте тестовому окну соответствующий `min_size` перед запуском сцены.

В `portrait_stage_reward` проверяется фактическая альфа картинки, свечения и действий после вступления родительского блока, включая итоговую награду уровня. Также отслеживаются появление плашки заработанных звёзд во время выплаты, побеление закрытого сундука перед взрывом и восстановление его теней после вспышки. GPU-сценарий `composited_fade_render` воспроизводит сбор родителем изначально скрытых элементов крупной награды: в RU/EN, с рекламной кнопкой и без неё, проверяются видимые пиксели картинки, суммы, свечения, кнопки и отложенного текста, промежуточная прозрачность, полное скрытие и восстановление. В настоящей последовательности итоговой награды он сравнивает кадры с плашкой/белым слоем и без них при остановленных анимациях, проверяет осветление пикселей закрытого сундука и Z-слои меняющегося счётчика звёзд. Для сохранения этих кадров задайте `HANGMAN_UI_CAPTURE_DIR` на доступный каталог вне проекта. Одного успешного начисления или разблокировки кнопки недостаточно для проверки видимости.

`portrait_stage_reward` дополнительно проверяет обе иконки рекламной кнопки ×2 и восемь слоёв их теней при повторных переключениях disabled/enabled после вступления. В GPU-сценарии проверяются видимое приглушение и восстановление кнопки, два цикла каждого блика на монетах и сундуке, скрытие/восстановление родителя, остановка и уход после повторного запуска эффекта. Для grayscale-иконок, скруглённой маски и обоих режимов отметки букв сравниваются пиксели при нулевой, половинной и полной альфе через родительскую модуляцию и `branch`; исходные mask/reveal/opacity-параметры остаются активны.

## Известные ограничения

Открытые сбои и непроверенные сценарии описаны в [аудите проекта](../docs/PROJECT_AUDIT.md). Успех отдельных наборов не подтверждает готовность Android-релиза. Прежние результаты и изменения запускателей доступны в Git.

`leaderboard_ui` проверяет пустой экран ошибки без кешированных строк и закреплённого игрока, игнорирование кеша после сбоя и при повторной попытке, восстановление по свежему ответу, переключение вкладок и уход. Центрирование текста в стиле комментария к слову и стандартной оранжевой кнопки проверяется в RU/EN при 960×1600, 690×1536 и 1080×1920; GPU-снимки сохраняются при `HANGMAN_UI_CAPTURE_DIR`.

`leaderboard_ui` дополнительно проходит настоящий сервис с mock-транспортом: успешный прогрев кеша, повторное открытие без сети, переход Retry в загрузку и немедленную пользовательскую попытку во время backoff, новый экземпляр сервиса с сохранённым ростером, отказ авторизации и восстановление после подключения. `leaderboard` и `network_retries` проверяют сохранение кеша/очереди звёзд и действующих ограничений повторов.

Сохранение редактора профиля проверяет `profile_ui`: серое состояние «Подождите...» без цены, блокировка повторных нажатий/редактирования/закрытия, ошибка сервера через верхний тостер, повторная отправка без повторного списания и закрытие только после подтверждения, поздний ответ после удаления редактора. `leaderboard` проверяет ожидание реального worker, отказ транспорта, backoff и подтверждённый профиль. GPU-прогон сохраняет `profile-saving-*` и `profile-save-error-*` при `HANGMAN_PROFILE_PREVIEW_DIR`; проверяйте оба языка и размеры 960×1600/690×1536.

`profile_ui` дополнительно проверяет собственные disabled-флаги всех стрелок, рандомайзера и кнопок рамок во время запроса, read-only имени, игнорирование поздних pressed-сигналов и восстановление доступности после ошибки. Блокировка применяется и к интерактивному счётчику магазина над формой.

`leaderboard_ui` проверяет сохранение живых строк/закреплённой карточки и кеша при открытии/обновлении, очистку только по реальной ошибке, устойчивое состояние Loading при повторном Retry, скрытие кнопки на время загрузки и центрирование «Загрузка…» в RU/EN при 960×1600, 690×1536 и 1080×1920. GPU-прогон дополнительно сохраняет `leaderboard_loading_*`.

`network_retries`, `leaderboard` и `leaderboard_ui` разделяют фоновые и пользовательские попытки: UI немедленно обходит паузу только для своей попытки, включая auth; таймеры фоновых повторов и очередь викторины сохраняются. Проверяется ручное сохранение за ошибочным фоновым запросом, один активный RPC, отсутствие утечки manual-флага, а также обычный `refresh(true)` без UI-признака, сохраняющий backoff.

`leaderboard_ui` проверяет выбор начальной вкладки до `_ready()`: при открытии «Турнира» нет вызовов глобального сервиса/кеша; первый вход на «Глобальный» делает ровно один запрос, повторное нажатие выбранной вкладки и возврат в «Турнир» не дублируют его. Повторный вход в «Глобальный» запускает новое обновление.

`profile_ui` проверяет тост успешного серверного сохранения с зелёной галочкой и положение системного тостера ниже хедера со счётчиками. `tournament_start_popup` проверяет переход кнопки «Погнали» к выбору темы; крестик, Back и истечение таймера только закрывают введение. `tournament_ui` проверяет восстановление нативного баннера и его слота после перехода к награде турнира.

`tournament_ui` проверяет общий со стартовым попапом счётчик с часами под подписью вкладки «Турнир»: нижняя граница вкладок проходит через его центр в обоих языках и трёх размерах окна. Все места, включая 1–3, находятся в одном прокручиваемом списке без закреплённого призового блока. У первых трёх строк — стандартные медали как в попапе завершения; награда находится справа от ника, слева от счётчика звёзд. Проверяются размеры обычных строк, порядок мест, суммы наград, отсутствие пересечений и сохранение прокрутки при обновлении таймера.

Компактность строк рейтинга: `leaderboard_ui` проверяет уменьшенные на 15% отступ аватарки и ширину счётчика, центрирование медали в оставшемся поле; `tournament_ui` — общую со звездой лёгкую шейдерную тень награды, сближение со счётчиком, увеличенную и поднятую сумму монет поверх иконки. Таймер турнира остаётся на полосе вкладок и продолжает обновляться при выборе глобального рейтинга; обе маски списка имеют одинаковый верхний отступ.

`leaderboard_ui` проверяет отсутствие дополнительного верхнего отступа первой строки при переключении вкладок и сдвиг звезды счётчиков на две единицы влево.

`leaderboard_ui` сравнивает текстуру, материал шейдерной тени и порядок слоёв звезды списка с настоящим счётчиком Home. Прозрачность тени задаётся общим `resource_counter_style.gd`, дополнительный сдвиг звезды списка составляет четыре единицы влево относительно HUD.

Числа звёзд центрируются в общей с HUD текстовой зоне (`resource_counter_style.value_rect`), а не в остатке плашки после иконки. `leaderboard_ui` проверяет видимые пиксели цифр на GPU для коротких значений, геометрию крупных значений и отсутствие наложения на звезду.

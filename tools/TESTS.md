# Актуализация тестов

Патч применяется после `hangman_quiz_selection_fix.patch`. Изменены только инструменты разработки в `tools/`.

## Что изменено

- Тесты адаптации, вводного режима и интеграции викторины используют отдельные фиксированные входные данные `tests/mechanics_balance.json`. `mechanics_fixture.gd` подставляет их в память процесса и синхронизирует уже созданный GameState. Игровой JSON не перезаписывается. Числовые ожидания в этих тестах относятся к фикстуре, а не к постоянно редактируемому балансу.
- Исправлено устаревшее ожидание прироста на шестой победе: для зафиксированного набора настроек это 0.0021.
- `quiz_expansion.gd` проверяет весь актуальный каталог вместо пакета из 30 вопросов с историческими ID. Убрано требование ровно 110 вопросов на тему.
- Сценарий продолжения викторины теперь подготавливает выбранный язык, очищает предыдущие сессии и завершает предшествующие этапы. Отсутствующий сохранённый блок приводит к провалу проверки, а не аварийному обращению к отсутствующему полю.
- Проверка пояснений сопоставляет их с актуальными ID вопросов, выявляет дубли и лишние/отсутствующие пояснения; число 1100 больше не зафиксировано.
- В UI-тестах предусмотрен сигнал окончания кадра для headless-рендера, чтобы переходы не зависали.
- `verify_optimization.py` проверяет точки входа, ссылки на ресурсы и каталог. Удалены хрупкие проверки конкретных строк, имён локальных переменных, числа вызовов и оформления кода. Этот скрипт не заменяет поведенческие тесты производительности, рекламы или UI.
- `verify_game_design_config.py` проверяет корректность текущего игрового конфига: границы сложности, таблицы, допустимость слотов, наград и таймеров. Убраны требования старых наград, конкретных скоростей анимаций и старого распределения этапов. В проверку используемых настроек добавлен селектор викторины.
- `verify_quiz_catalog.py` учитывает новое расширение набора вниз по сложности, проверяет настройку минимума кандидатов и наличие безопасного вопроса на сетке сложности с шагом 0.01.

## Запуск

После импорта ресурсов в Godot, на Linux:

```sh
python3 tools/run_content_tests.py --godot /path/to/godot
python3 tools/verify_game_design_config.py
python3 tools/verify_optimization.py
```

`run_content_tests.py --suite quiz_expansion` запускает отдельный сценарий. Каждый запуск Godot получает собственный временный каталог сохранений. Запуск считается успешным только при нулевом коде завершения, наличии итогового отчёта без ошибок и отсутствии `ERROR` / `SCRIPT ERROR`. Зависшие тесты завершаются по таймауту с выводом журнала.

Тесты наград, сейвов, рекламы и согласий сохранены; их существующие команды запуска остаются действующими. Они не входят в `run_content_tests.py`.

## Выполненная проверка (Godot 4.6.1)

| Набор | Проверки | Ошибки |
|---|---:|---:|
| Адаптация | 16 | 0 |
| Вводный режим | 48 | 0 |
| Каталог, размещение и продолжение викторины | 11038 | 0 |
| Пояснения и показ результатов | 8919 | 0 |
| Подбор викторины | 2115 | 0 |

Большие числа — повторные проверки на каждой записи обоих языков, а не тысячи отдельных сценариев. Полная проверка текстов расширила охват каталога.

Структурный валидатор и валидатор игрового конфига прошли. Дополнительно проверено, что валидатор принимает изменённые допустимые награды и отклоняет неверный порядок временных окон, нулевой размер набора и слот за пределами уровня.

При завершении двух UI-наборов Godot сообщает `ObjectDB instances leaked at exit`; ошибок скриптов нет. Предупреждение не скрывается запускателем. Полный аудит освобождения UI-объектов и запуск Android-сборки в эту правку не входят.

# Положительные результаты и звёзды заполнителей

Применяется поверх миграции 008. UI не меняется. В Supabase SQL Editor выполните **`supabase/migrations/009_leaderboard_positive_stars.sql`**. Она заменяет обе функции dev/production, сохраняя записи, ID, ники и правила смешивания. Старые миграции после 009 повторно не запускайте.

## Реальные участники

В топ попадают только игроки с рекордом `stars > 0`. Они же учитываются в `total_players` и «Топ N%». Если своего положительного результата ещё нет, `me=null`.

Клиент не ставит 0 в очередь отправки. Сервер также принимает `p_stars=0` без создания или изменения записи. Старые нулевые строки физически остаются в таблицах, но исключаются из всех расчётов и ответов. Позднее положительное значение улучшает эту же запись, сохраняя ID. Уже положительный рекорд не уменьшается, как и раньше: рейтинг хранит лучший результат.

## Звёзды заполнителей

1. Берём положительные реальные строки текущего топа.
2. `N` — минимальное число звёзд среди них.
3. `K` — сколько строк не хватает до 100.
4. Если `K >= 2`, для заполнителя с индексом `i` от 0 до K−1:

   `stars(i) = ceil(N − N × i / (2 × (K − 1)))`.

Оба конца диапазона включены: первый получает N, последний — ceil(N/2). Округление выполняется после интерполяции, а не до неё. Используется SQL numeric, чтобы не потерять точность или переполнить промежуточные произведения на больших результатах.

Пример: 95 реальных участников, у последнего 100 звёзд. Для пяти заполнителей получатся **100, 88, 75, 63, 50**. Для N=101 — **101, 89, 76, 64, 51**.

- `K=1`: единственный заполнитель получает N.
- `K=0`: заполнителей нет.
- `N=1`: у всех заполнителей по 1 звезде; повторяющиеся значения при целочисленном округлении допустимы.
- Ни у реальных строк, ни у заполнителей в ответе нет 0.
- Реальные игроки всегда идут перед заполнителями, в том числе при одинаковом числе звёзд.

Значения вычисляются при запросе по текущему реальному минимуму и не сохраняются как игровой прогресс. При изменении состава реального топа значения пересчитываются. Фиктивные аккаунты и награды не создаются. Заполнители не входят в численность или проценты реальных участников.

## Пустой рейтинг

Если положительных результатов ещё нет, взять N неоткуда. Сервер возвращает `top=[]`, `total_players=0`, `me=null`. Нулевые или произвольно выбранные положительные звёзды не подставляются. После появления первого реального положительного результата список дополняется до 100 строк.

## Ники и язык

Выбор имён не меняется: 60% СНГ + 40% английских для русского интерфейса, 20% СНГ + 80% английских для английского. Пропорции считаются от числа заполнителей с округлением. Случайный выбор стабилен для аккаунта; в исходном пуле каждого региона 80 казуальных и 20 молодёжных ников.

## Проверки

```bash
NODE_PATH=<node_modules с @electric-sql/pglite> node tools/tests/leaderboard_sql.cjs
python3 tools/run_content_tests.py --godot <Godot> --suite leaderboard
```

Проверяются скрытие старых нулевых записей, отсутствие регистрации при отправке 0, пустой положительный рейтинг, точная интерполяция и оба конца диапазона, нечётный N, N=1, максимальное значение, один/несколько/никаких заполнителей, порядок при равенстве, прежнее смешивание имён, проценты на 10 000 положительных участников и независимость dev/production. Клиент отвергает нулевые строки и заполнители без реального положительного основания.

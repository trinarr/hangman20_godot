# Открытые проблемы проекта

Это список открытых задач, а не полный аудит каждой функции или развёрнутой инфраструктуры. Дата, среда и границы проверки указаны в соответствующем пункте. Закрытые пункты и история изменений доступны в Git; команды проверок — в [tools/TESTS.md](../tools/TESTS.md).

## 5. Размер главных скриптов

Пункт 5 исходного аудита остаётся открытым. Большая часть создания интерфейса и маршрутизации сосредоточена в `scripts/main_portrait.gd`; также крупны `scripts/main.gd` и `scripts/core/game_state.gd`. Это усложняет поиск зависимостей и локальные изменения, но само по себе не доказывает проблему производительности.

При следующих UI-задачах выделять самостоятельные компоненты по существующим образцам popup, результата и награды. Не совмещать исправление поведения с общей переписью. Сохранять [контракты архитектуры](ARCHITECTURE.md) и проверять жизненный цикл узлов.

## Остаточная диагностика

Подробная рекламная диагностика использует общий debug-переключатель `yandex_ads/logging_enabled`, по умолчанию false; release её отключает. Обычные ошибки загрузки баннера сохраняют код, описание SDK требует включения диагностики. Лидерборд выводит сводные количества и собственный ранг/звёзды без ID и ников строк. Это не подтверждает отсутствие самостоятельных логов сторонних SDK в release APK.

## Производительность экранов профиля и рейтинга

Проверка 26 октября 2026 на Windows / Godot 4.7.2, скрытый GPU, 960×1600, изолированный профиль и отключённая сеть. Это измерения debug-сборки на ПК, не FPS Android.

- **P2: цена первого построения глобального списка.** Повторный snapshot обновляет существующие строки, но первое открытие по-прежнему создаёт все 100 карточек. После прогрева медиана первого `set_snapshot` — 172 мс, в открытом рейтинге 2368 узлов. Для снижения этой задержки рассмотреть пул видимых строк; отдельно измерить на Android. Повторный идентичный snapshot в том же прогоне занимает около 0.4 мс.
- **Кандидат для GPU-профиля:** `colored_icon_outline.gdshaderinc` семплирует исходник и 16 соседей даже для полностью непрозрачной заливки. Рассмотреть ранний выход для alpha=1 после вычисления производных, сохраняя полный алгоритм для края; сравнить вид и GPU-время на Android. Иконки с обводкой в шейдерных слоях тени повторяют эту работу в каждом слое.

## Покрытие регрессий обводки

`colored_icon_outline_render` измеряет толщину на `SubViewport` 400×400 при разных масштабах иконки; проверки настоящих popup в двух размерах окна проверяют параметры материалов и наличие теней, но не фактическую толщину обводки. При следующей правке общей обводки расширить существующее измерение на растянутый корневой viewport. Это пробел покрытия, а не подтверждённый дефект текущей графики. Ожидаемое поведение обводок и масштабируемых рамок закреплено в [архитектуре](ARCHITECTURE.md#жизненный-цикл-интерфейса).

## Доверие к лидерборду

`supabase/migrations/010_leaderboard_local_fillers.sql` принимает клиентский `p_stars` с проверкой диапазона и сохраняет улучшение рекорда. Серверного доказательства заработанных звёзд в этой функции нет. Для защиты соревновательного рейтинга от модифицированного клиента нужен серверный источник начислений либо проверяемый протокол результата. Диагностика развёрнутой БД на чтение выполнена 05.11.2026; этот контракт доверия к клиентскому результату сохраняется.

05.11.2026 в Supabase `Hangman 2.0` выполнены только согласованные диагностические SELECT 01–04. Все 48 проверяемых столбцов и восемь RPC имеют ожидаемые типы/сигнатуры; индексы готовы и валидны, ограничения валидированы. Хеши тел восьми RPC совпадают с последними локальными определениями из 017/018 при CRLF. Приватные таблицы имеют RLS; у anon/authenticated нет прямых прав и USAGE приватных схем. Проверенные агрегаты без нарушений, счётчики population совпадают с положительными игроками; ожидающих блокировок и накопленных deadlock нет. История миграций не зарегистрирована либо не видна: полнота всей последовательности DDL этим не доказана. Данные и настройки сервера не менялись.

Остаются предупреждения Supabase Advisors: EXECUTE для anon у служебной `public.rls_auto_enable` ([описание проверки](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)) и отключённая защита скомпрометированных паролей ([описание](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)). Функция не вызывалась, её фактическая доступность как RPC не проверялась. SECURITY DEFINER для игровых authenticated RPC и отсутствие политик на полностью закрытых приватных таблицах сами по себе не доказывают утечку. Неиспользованный индекс `players_tournament_sample_idx` оставлен до нагрузочного измерения; накопительная статистика не доказывает его ненужность.

## Проверки перед релизом

Новые ники ограничены на клиенте русскими/английскими буквами с Ё/ё, цифрами 0–9 и одиночными обычными пробелами. RPC `leaderboard_sync` / `leaderboard_sync_dev` в миграции 017 пока проверяют только длину, края и управляющие символы. Для защиты от обхода клиентской валидации нужна следующая миграция с тем же набором допустимых символов; учесть ранее сохранённые имена и старые клиенты.

- Завершить приёмку настоящей release-подписи и доставки AAB по [инструкции Android](../tools/EXPORT.md). Home/профиль RU/EN и настройки EN проверены на телефоне; это не полная матрица UI. Для прозрачности отдельно проверить блики монет/сундука, переключение рекламной кнопки ×2, затухание серых иконок подсказок/темы комментария, аватар при уходе с главного экрана и приглушение отметок использованных букв: проверки материалов и компонентов на настольном GPU не подтверждают все эти переходы на Android.
- Повторять проверку состава пакета при изменении фильтров. Текущие APK/AAB прошли проверку runtime-ресурсов и исключений документации/служебных файлов; это не универсальный поиск любых секретов.
- Уточнить историю применённых миграций и ограничения клиентских API-токенов. Текущие сигнатуры/тела RPC, права/RLS и агрегаты dev/prod сверены диагностикой на чтение; наличие SQL в Git само по себе состояние сервера не подтверждает.
- Подтвердить изоляцию тестового профиля на Linux, если эта среда используется; последний фактический прогон выполнен на Windows.
- Региональный запускатель проверен на Windows 05.11.2026: фактический временный `user://` подтверждается до игровых autoload; IPinfo token удалён, Supabase-сеть отключена. Добавлены отсутствовавшие `symbols`/`scenes`, итоговый PASS проверяется вместе с engine.log. Изоляция и отсутствие ошибок не выводятся из одного кода завершения.

05.11.2026 обязательные GPU-наборы `rewards`, `save_recovery`, `resume_flow`, `runtime_optimizations`, `release_reward_regression` прошли соответственно 297/73/25/49/44 проверки в изолированных профилях. `resume_flow` подтверждает сохранение 50/50 и отсутствие повторных звёзд за скорость после восстановления викторины. На Android процесс остановлен во время фактически показанного Rewarded с незаработанным receipt: после запуска остались 200 монет и лимит 5, ложной выплаты нет. Это не проверка остановки в узком окне после получения reward callback до записи receipt. Незаработанный receipt сохраняется намеренно для позднего callback и сам по себе не является дефектом очистки.

# Открытые проблемы проекта

Состояние по результатам локальной проверки от 18 октября 2026 на Windows / Godot 4.7.2. Это список открытых задач, а не полный аудит каждой функции или развёрнутой инфраструктуры. Закрытые пункты и история изменений доступны в Git; команды проверок — в [tools/TESTS.md](../tools/TESTS.md).

## 5. Размер главных скриптов

Пункт 5 исходного аудита остаётся открытым. Большая часть создания интерфейса и маршрутизации сосредоточена в `scripts/main_portrait.gd`; также крупны `scripts/main.gd` и `scripts/core/game_state.gd`. Это усложняет поиск зависимостей и локальные изменения, но само по себе не доказывает проблему производительности.

При следующих UI-задачах выделять самостоятельные компоненты по существующим образцам popup, результата и награды. Не совмещать исправление поведения с общей переписью. Сохранять [контракты архитектуры](ARCHITECTURE.md) и проверять жизненный цикл узлов.

## Производительность экранов профиля и рейтинга

Проверка 26 октября 2026 на Windows / Godot 4.7.2, скрытый GPU, 960×1600, изолированный профиль и отключённая сеть. Это измерения debug-сборки на ПК, не FPS Android.

- **P2: цена первого построения глобального списка.** Повторный snapshot обновляет существующие строки, но первое открытие по-прежнему создаёт все 100 карточек. После прогрева медиана первого `set_snapshot` — 172 мс, в открытом рейтинге 2368 узлов. Для снижения этой задержки рассмотреть пул видимых строк; отдельно измерить на Android. Повторный идентичный snapshot в том же прогоне занимает около 0.4 мс.
- **Кандидат для GPU-профиля:** `colored_icon_outline.gdshaderinc` семплирует исходник и 16 соседей даже для полностью непрозрачной заливки. Рассмотреть ранний выход для alpha=1 после вычисления производных, сохраняя полный алгоритм для края; сравнить вид и GPU-время на Android. Иконки с обводкой в шейдерных слоях тени повторяют эту работу в каждом слое.
- **P3: лишние аллокации при смене вкладки.** `tabbed_page_style.select` создаёт пять одинаковых прозрачных `StyleBoxFlat` для каждой из двух кнопок при каждом настоящем переключении. Настроить эти состояния один раз в `configure`, сохранив в `select` только состояние и анимацию. Рост ресурсов в прогоне не обнаружен, это замечание о стоимости переключения, а не доказанная утечка стилей.

## Неполное применение обводки иконок

Проверка по коду 26 октября 2026, без отдельного GPU-прогона анимации:

- Летящие монеты и звёзды `_play_single_player_reward_resource_collection` получают стандартные 2 px, тогда как исходные иконки цепочки наград используют 5 px. Требуется согласовать толщину при переходе из цепочки в HUD: применение 2 px начинается уже у источника, а не только у счётчика.

## Доверие к лидерборду

`supabase/migrations/010_leaderboard_local_fillers.sql` принимает клиентский `p_stars` с проверкой диапазона и сохраняет улучшение рекорда. Серверного доказательства заработанных звёзд в этой функции нет. Для защиты соревновательного рейтинга от модифицированного клиента нужен серверный источник начислений либо проверяемый протокол результата. Развёрнутая БД не проверялась.

## Проверки перед релизом

Новые ники ограничены на клиенте русскими/английскими буквами с Ё/ё, цифрами 0–9 и одиночными обычными пробелами. RPC `leaderboard_sync` / `leaderboard_sync_dev` в миграции 017 пока проверяют только длину, края и управляющие символы. Для защиты от обхода клиентской валидации нужна следующая миграция с тем же набором допустимых символов; учесть ранее сохранённые имена и старые клиенты.

- Собрать APK/AAB по [инструкции Android](../tools/EXPORT.md) и проверить на устройстве оба языка, шрифты, анимации, сохранения и нативную рекламу. Настольные тесты это не подтверждают. Для прозрачности отдельно проверить блики монет/сундука, переключение рекламной кнопки ×2, затухание серых иконок подсказок/темы комментария, аватар при уходе с главного экрана и приглушение отметок использованных букв: проверки материалов и компонентов на настольном GPU не подтверждают все эти переходы на Android.
- Проверить состав пакета после изменения фильтров: runtime-ресурсы присутствуют, документация и секреты отсутствуют. Корневые README/AGENTS требуют отдельной проверки состава.
- Сверить применённые миграции, права RPC/RLS, dev/prod и ограничения клиентских API-токенов. Наличие SQL в Git не подтверждает состояние сервера.
- Подтвердить изоляцию тестового профиля на Linux, если эта среда используется; последний фактический прогон выполнен на Windows.
- Отдельно проверить запускатели рекламного/регионального согласия: у них собственные механизмы временных проектов; код завершения без итогового отчёта не подтверждает прохождение.

Из прежнего разбора сохранений остаются сценарии для повторной проверки на текущем коде: обработка `save_game() == false` обычными экономическими операциями, убийство Android-процесса между рекламой и callback, окно бонуса за скорость после восстановления викторины. Они не считаются подтверждёнными дефектами текущего состояния без воспроизведения.

## Надёжность пересборки MSDF-профилей

Текущие 12 шрифтов имеют корректные MSDF-import-настройки. Замечания относятся к будущему изменению набора профилей:

- `tools/build_ui_msdf_fonts.py` создаёт TTF, но не создаёт/проверяет их `.import`. Новый профиль без сохранённых метаданных может импортироваться как raster, хотя `ui_fonts.gd` выберет его по существованию файла. Глобальная настройка default font не задаёт режим пользовательских TTF. Генерации нужна проверка импортов всего ожидаемого набора, включая `multichannel_signed_distance_field`, размер MSDF и pixel range.
- `_roboto_flex_font()` молча возвращается к raster при отсутствии подготовленного профиля и не проверяет фактический MSDF-режим загруженного файла. Добавить диагностику отсутствующего/неверно импортированного профиля, сохраняя работоспособный fallback.
- `font_artifacts_render` сравнивает основные button/display-профили и regular; визуальные артефакты промежуточных ширин заголовка отдельно не проверяет. При расширении регрессии добавить эти профили, а также проверку MSDF-обводки на целевых размерах. Headless-проверка режима шрифта не заменяет эту проверку.

Реализация и объяснение разделения MSDF/raster описаны в [profile_settings_ui.md](profile_settings_ui.md). Правила параметров и ограничения MSDF — в [FontFile Godot 4.7](https://docs.godotengine.org/en/4.7/classes/class_fontfile.html#class-fontfile-property-multichannel-signed-distance-field). Проверка на Android и оценка задержки первой генерации глифов/расхода GPU-памяти остаются частью проверки устройства.

# Аудит проекта от 18 октября 2026

## Объём и результат

Проверены структура репозитория, точка входа, основные зависимости, механизм сохранений, организация контента, тестовые запускатели, загрузка графики, локальные SQL-контракты и существующие иконки. Запущены перечисленные ниже локальные проверки. Это обзор сопровождаемости с выборочным чтением кода, не полный аудит каждой функции, безопасности сервера или производительности на устройстве.

Рабочее дерево до начала аудита было чистым. Изменения по результатам — `AGENTS.md`, правила иконок и этот отчёт; игровая логика, данные, графика и манифесты не исправлялись. Контактный лист для визуального анализа создан вне репозитория.

Сильная сторона проекта — наличие единой конфигурации баланса, общих UI-модулей, постоянных ID контента, миграционного механизма сохранений и большого набора регрессий. Главный недостаток рабочего процесса — отсутствие компактной актуальной инструкции, объединяющей эти контракты и отделяющей их от исторических patch-документов. Теперь это назначение выполняет корневой `AGENTS.md`.

## Состояние при первоначальном аудите

### Высокий приоритет: воспроизводимость проверок

1. **Кодировка Python на Windows.** `verify_word_catalog.py`, `verify_word_content_migration.py` и `verify_quiz_catalog.py` читают часть JSON через `Path.read_text()` без encoding. В текущем окружении стандартная cp1251 вызывает `UnicodeDecodeError`; через quiz-валидатор падает и `verify_optimization.py`. С `PYTHONUTF8=1` каталоги и миграционные данные проходят. Рекомендуемое исправление инструментария: явная UTF-8 при чтении/записи и в дочерних процессах; текущий безопасный способ запуска указан в AGENTS.

2. **Ложное сообщение о пропавшем шрифте.** После устранения проблемы кодировки `verify_optimization.py` сообщает `Missing runtime resources: scripts/ui/ui_fonts.gd -> res://fonts/msdf/RobotoFlexUI_`. Его regexp обрывает форматную строку на `%`. В `ui_fonts.gd` это шаблон `RobotoFlexUI_%d_%d_%d_%d_%d.ttf`, проверяемый через `ResourceLoader.exists`, а не буквальное имя файла. Файлы соответствующего семейства присутствуют. Это подтверждённый дефект статического валидатора, а не подтверждение отсутствия runtime-шрифта. Следует разбирать динамические шаблоны отдельно и проверять реально используемые профили.

3. **Запускатели контента и наград требуют Linux.** `run_content_tests.py` и `run_reward_tests.py` явно отклоняют Windows, потому что изолируют сохранения через `XDG_DATA_HOME`. Прямой запуск их сцен на Windows может затронуть реальный профиль. Следующий шаг: кроссплатформенная изоляция через отдельный тестовый проект/user directory либо Linux CI/WSL с Linux Godot. Платформенную проверку удалять без замены изоляции нельзя.

6. **Документация содержит исторические состояния — исправлено 18 октября 2026.** При первоначальном аудите `tools/TESTS.md`, `tools/EXPORT.md`, `tools/REWARDS.md`, `docs/OPTIMIZATION_REVIEW.md` смешивали инструкции и сведения о старых патчах, количествах записей, наградах и Godot 4.6.1. ## Дополнительные риски по локальному коду

- В `supabase/migrations/010_leaderboard_local_fillers.sql` RPC принимает клиентский `p_stars` в диапазоне до 2 000 000 000 и сохраняет улучшение рекорда. Серверного подтверждения заработанных звёзд в этой функции нет: модифицированный клиент может заявить завышенный результат. Если нужен соревновательный рейтинг с защитой от накрутки, потребуется серверный источник начислений или проверяемый протокол результатов. Это вывод из SQL в репозитории; состояние развёрнутой БД не проверялось.
- В миграциях есть RLS, разграничение dev/prod, `security definer` с заданным `search_path` и ограничения прав RPC. Наличие этих механизмов не подтверждает корректность всех прав в работающей БД. Серверные миграции не применялись.
- В `project.godot` есть клиентские настройки API, publishable key и токен определения региона. Их значения в отчёте не дублируются. Publishable key рассчитан на клиент; для остальных токенов нужно отдельно проверить назначение, квоты и ограничения у провайдера. Секретные server-side ключи и ключи подписи в клиент добавлять нельзя.
- Актуальная полнота экспортных фильтров после добавления корневых документов требует проверки пакета при следующем экспорте: `docs/*` уже исключён, `AGENTS.md` лежит в корне. Само наличие файла в репозитории не подтверждает его включение в PCK.

## Исправления высокого приоритета от 18 октября 2026

Пункты 1–3 первоначального аудита исправлены:

- В Python-инструментах и фикстурах добавлена явная UTF-8 при чтении/записи, включая импортируемые модули валидаторов и ConfigParser экспортных настроек. Проверки слов, миграций и структурного валидатора повторены с `PYTHONUTF8=0`.
- Структурный валидатор разбирает целые строковые пути. Форматные пути проверяются на наличие файлов соответствующего семейства; отсутствующий буквальный ресурс или пустое семейство по-прежнему приводят к провалу. Это структурная проверка; она не доказывает существование каждого вычисляемого варианта, для чего нужны игровые UI/шрифтовые сценарии.
- Запускатели контента и наград поддерживают Windows/Linux. Общий модуль меняет только окружение дочерних процессов и до запуска игровых autoload подтверждает путь `user://` во временном профиле. Применяются проверка отчёта, проверка ошибок и чтение файла журнала для Windows GUI-бинарника. Фазы восстановления разделяют профиль; независимые сценарии изолированы друг от друга. Android-настройки и игровая логика не изменены.
- Добавлены регрессии: пропавший ресурс, непустой/пустой динамический шаблон, отказ при небезопасном пути сохранений, отказ при пустом журнале и ошибках движка. Проверка настоящим Godot подтверждает сохранение между процессами, отсутствие данных в следующем профиле и неизменность окружения родителя.

## Исправление пункта 4 от 18 октября 2026

Перед обновлением манифеста проверены все девять расхождений. Файлы полностью совпадают с версиями в текущем Git HEAD, открываются как PNG и имеют потребителей в игровых скриптах. Изменение английского логотипа присутствует в истории Git (`65ea08c`, «Переработка анимаций бумажки»). Визуально просмотрены все девять изображений; их размеры и цветовые режимы сверены с файлами. Русский логотип намеренно имеет RGB и зелёную подложку: `main_portrait.gd` включает для него `title_chroma_key`, а `home_logo_paper_reveal.gdshader` удаляет подложку при отрисовке. Конвертация этого исходника в RGBA для исправления манифеста не требуется.

После сверки выполнен существующий `tools/upscale_art_2x.py --refresh-manifest`:

- Добавлены восемь перечисленных выше записей с фактическими размерами, режимами и SHA-256. Они отмечены `native_2x`: уже подготовленные к использованию растры, которые не нужно повторно увеличивать.
- Обновлён только `target_sha256` английского логотипа; прежний `source_sha256` сохранён как историческое значение.
- `file_count` изменён со 148 на 156. Область манифеста осталась прежней: `icon.png`, PNG в `flash_assets/` и `img/`. Число 165 в аудите текстур включает дополнительные каталоги и не должно совпадать со 156.
- Остальные записи и манифест sharpening пяти иконок сохранены. Ресэмплинг и перезапись PNG не выполнялись.

Проверки после изменения: `upscale_art_2x.py --verify` проходит для 156 растров; `audit_texture_usage.py` проходит для 165 текстур (missing/unreferenced/dynamic = 0). Контрольные суммы всех PNG в области манифеста до и после исправления совпадают; пять refined-иконок согласованы с обоими манифестами. Пункт 4 закрыт.

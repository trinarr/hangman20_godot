# Продолжение аудита: срок жизни эффектов награды

Патч `hangman-2.0_v6_optimization_rewards.patch` применяется **непосредственно**
к проекту из `hangman-2.0(6).zip`. Он объединяет предыдущую очистку и исправления
срока жизни наград. Старые патчи перед ним применять не нужно.

## Адаптация к обновлённым исходникам

Новый архив ещё не содержал изменений двух предыдущих патчей. Изменения
перенесены трёхсторонним слиянием с общей базой из архива `(5)`.

- Сохранены все пользовательские добавления и удаления строк `main_portrait.gd`:
  лента `НОВАЯ` / `NEW`, расчёт границ текста, слои, тень и анимация карточек.
  Разница между общей базой и пользовательской версией точно совпадает с
  разницей между прежним исправленным кодом и результатом объединения.
- `badge_shadow_style.gd`, `display_text_effect.gd`, `theme_new_badge.gdshader`
  и его UID, CSV и оба файла перевода сохранены побайтово из нового архива.
- Объединённый патч содержит необходимые шейдеры, удаление устаревшего кода,
  актуальные проверки и runner. Его база — новый архив, а не предыдущий патч.
- На объединённой версии повторно выполнены 241 проверка наград, 236 проверок
  переходов викторины и три статических валидатора. Дополнительно открыт
  выбор темы после третьего уровня: лента видима и показывает `НОВАЯ` / `NEW`
  в соответствующей локализации. Ошибок движка в этих игровых запусках нет.

## Исправления

В исходной реализации `_clear()` очищал RuntimeUI, но CanvasLayer летящих
ресурсов и некоторые tween счётчиков оставались у Main. Новый экран мог получить
старые попадания, промежуточный баланс и callback перехода к результату.

- Слои полёта теперь имеют общего владельца `RewardPresentationEffects`.
  При смене экрана он удаляется из дерева, а его узлы освобождаются.
- Tween полёта и изменения баланса регистрируются для синхронной отмены.
  Обычная привязка к исходному узлу сохраняется. Завершённые tween удаляются
  из списка при регистрации следующего; список очищается при смене экрана.
- Сохраняемая шапка результата возвращается к обычным размерам и фактическому
  балансу. Отмена tween больше не оставляет счётчик в увеличенном состоянии.
- Отложенное продолжение последнего этапа проверяет поколение экрана.
  Такая же проверка защищает старт выплаты после ожидания кадра и показ
  монет на Home после рекламы, если пользователь успел перейти дальше.
- Общий путь полёта используется и для монет, и для звёзд викторины/попыток;
  их изменение баланса также отменяется при очистке экрана.
- Отложенная раскладка фонового узора использует существующий helper
  `_run_for_live_control`: удалённый Control не передаётся в типизированный метод.
- Удалены невызываемые `_set_portrait_resource_counter_collection_active_legacy`
  и `_finish_portrait_resource_counter_collection_settle`, а также чтение
  метаданных, которые записывала только старая анимация.
- Добавлены созданные Godot UID для двух шейдеров из предыдущего патча.

Формулы выплат, формат сохранений и обработка рекламных квитанций не менялись.
Из GameState удалены только ранее найденные неиспользуемые методы.
В обработчике закрытия рекламы добавлена только передача поколения экрана
отложенному визуальному эффекту. Начисление остаётся независимым от анимации.
Тайминги, количество летящих иконок, оформление и баланс сохранены.

## Проверки

Проверено в **Godot 4.6.1 stable, Linux, headless**:

- `tools/tests/rewards.tscn`: **241 проверка, 0 нарушений**. В число входят
  проверки геометрии текстовых слоёв; это не 241 отдельный игровой сценарий.
  Проверяются объединённый итог, автоматический переход, обычные/сложные уровни,
  поражение последнего этапа и ноль побед, одноэтапный уровень, викторина,
  идемпотентность выплат, пределы валют, восстановление сохранений, старые награды,
  RU/EN, размеры 690×1536 и 960×1600.
  Рекламные события имитируются с настоящими request_id GameState: повтор,
  повторная попытка для той же награды, закрытие до начисления, чужой id,
  отменённый запрос, поздняя выплата старой награды при новом предложении.
  Отдельно проверены отмена полёта, отсутствие старого callback, сохранённая
  шапка, монетный/звёздный HUD и отмена отложенного перехода/эффекта.
- Первые 203 проверки были запущены **до исправления runtime-кода**: три
  нарушения — оставшийся слой, старый callback и повторное открытие результата.
  После исправления эти же проверки прошли. Расширенный набор дополнительно
  выявил ошибку отложенной раскладки фона; в итоговом запуске её нет.
- `tools/tests/quiz_explanation_transition.tscn`: **236 проверок, 0 нарушений**,
  RU/EN, все три скорости верного ответа и неверные ответы. Общая анимация
  звёзд не нарушила появление пояснений и доступность продолжения.
- `verify_save_integrity.py` проходит. Старые проверки текста функций обновлены
  под объединённый экран, request_id и существующий helper запуска обучения.
- `verify_game_design_config.py` проходит: 200 runtime-ключей.
- `verify_optimization.py` проходит. Вместо устаревших условий о 800 вопросах,
  непрерывных ID и старых ограничениях сложности он запускает **существующий**
  `verify_quiz_catalog.py` без `--write`. Тот проверяет актуальный каталог,
  замены ID, порядок и соответствие runtime-файлам, варианты ответов и утечки
  ответа в формулировке. Удалены дублирующие старые списки и helpers.
- `git diff --check` и применение объединённого патча к чистой базе архива `(6)`
  проверены; содержимое и режимы всех полученных файлов совпадают с результатом.

Запуск тестов наград с временными сохранениями на Linux:

```bash
python tools/run_reward_tests.py --godot /path/to/godot
```

Перед первым запуском нужно импортировать проект в редакторе Godot.
Runner устанавливает отдельный `XDG_DATA_HOME`, ждёт до 120 секунд и требует
итоговый отчёт без нарушений. Он также проверяет ошибки движка: ошибка GDScript
может оборвать coroutine без ненулевого кода завершения процесса.
На других ОС runner останавливается, чтобы не затронуть настоящее сохранение.

Для дополнительного теста викторины также нужен отдельный профиль данных:

```bash
XDG_DATA_HOME=/tmp/hangman-quiz-tests godot --headless --path . tools/tests/quiz_explanation_transition.tscn
```

## Ограничения и следующие доработки

В итоговых запусках нет `ERROR`/`SCRIPT ERROR`, но при завершении Godot сообщает
`ObjectDB instances leaked at exit`. Предупреждение было и до этих исправлений;
подробный запуск показывает оставшиеся RefCounted. Причину нужно исследовать
отдельно, в том числе ожидания завершения отменённых анимаций. Утечки не считаются
исправленными этим патчем.

Визуальное сравнение, Android-экспорт, настоящий рекламный SDK и замеры FPS/GPU
не выполнялись. Импорт в 4.6.1 сообщает об отсутствии `preset.0/runnable`
в исходном export_presets.cfg; проект помечен как 4.7. Конфигурация экспорта
не менялась ради старшего/младшего формата редактора.

Приоритет следующих работ:

1. Вынести результат этапа, итог уровня и предложение x2 из `main_portrait.gd`
   в отдельный контроллер с явными состояниями. Существующие тесты использовать
   для сохранения порядка выплат и переходов.
2. Разобрать оставшиеся RefCounted при завершении и отмене экрана, затем
   измерить многократное открытие/закрытие результата на устройстве.
3. Профилировать на Android многослойный текст и фон из TextureRect: количество
   узлов, draw calls, CPU/GPU и память. Менять оформление по результатам замеров.
4. Проверить интервалы сложности каталога. Его валидатор сообщает, что часть
   высоких целевых сложностей обслуживается ближайшим доступным вопросом;
   это существующая особенность данных, а не изменение данного патча.

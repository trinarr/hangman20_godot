## Установка

1. Примените патч клиента.
2. Выполните в Supabase SQL Editor **только новую миграцию `supabase/migrations/007_leaderboard_fillers.sql`**, если 005 и 006 уже выполнены. Она содержит таблицы, все 200 утверждённых казуальных ников и новые версии обеих функций.
3. Запустите debug-сборку. В логах появятся количество реальных строк и заполнителей, ники, `is_filler` и язык.

Пример при одном реальном участнике:

```text
[Leaderboard] Top received: rows=100 real=1 fillers=99 total_players=1 language=ru
[Leaderboard] Top: rank=2 player=filler:cis:001 nickname=Павел stars=0 is_me=false is_filler=true
```

Никакие миграции в облаке автоматически не запускаются. Сначала требуется применить SQL; старая функция не принимает новый параметр языка. Ошибка не переключает debug на production, ожидающий результат остаётся для повторной отправки.

## Правила

- Сначала сервер выбирает до 100 реальных участников по прежним правилам звёзд и времени достижения.
- Если строк меньше 100, сервер добавляет недостающее число заполнителей в конец списка. Даже реальный игрок с 0 звёзд всегда выше заполнителя.
- У заполнителей 0 звёзд; они не имеют игрового прогресса, не получают наград и не растут автоматически вместе с результатом игрока.
- В каждой строке есть `nickname` и `is_filler`. ID заполнителя имеет вид `filler:cis:001` / `filler:us_europe:001`, что не пересекается с числовыми ID реальных участников.
- Ники и порядок привязаны к стабильным слотам 1…100 каждого пула. Повторное чтение не перемешивает список. При появлении нового участника сокращается хвост заполнителей.
- Если реальных участников 100 или больше, заполнителей нет.
- Заполнители не создают пользователей в Supabase Auth и не добавляются в таблицы `players`.
- `total_players`, точное место текущего игрока и «Топ N%» считаются только среди реальных участников. В пустом рейтинге `total_players=0`, `me=null`, но `top` содержит 100 заполнителей.
- Реальные участники пока получают отображаемое имя «Игрок ID» / «Player ID». Имена от пользователей и UI ввода не добавляются.

## Язык

Клиент отправляет `p_language` по **языку интерфейса** (`Database.interface_language`), независимо от языка базы слов. `ru` выбирает 100 ников СНГ, `en` — 100 США/Европы. Это только стиль имён: реальный рейтинг и место игрока общие для обоих языков одного окружения.

Сервер нормализует `ru-RU` / `ru_RU` в `ru`. Отсутствующее, неизвестное или null-значение выбирает английский пул. Ответ содержит нормализованное `language`.

Кеш учитывает язык. Смена языка не получает прежние ники из минутного кеша. Если язык поменялся во время запроса, устаревший снимок не публикуется сигналом leaderboard_ready; клиент получает новый. Подтверждённые звёзды при этом повторно не начисляются.

## Хранение и права

- Production: `leaderboard_private.fillers`.
- Dev: `leaderboard_dev_private.fillers`.
- В каждой таблице по 200 имён: 100 `cis` и 100 `us_europe`.
- Таблицы закрыты от прямого доступа anon/authenticated, RLS включён. Не добавляйте схемы в Exposed schemas.
- Клиент получает только выбранные сервером строки топа. Полный пул не читается клиентским кодом и исключён из экспорта игры вместе с папкой `supabase/`.

Исходный утверждённый список хранится в репозитории: `supabase/seeds/leaderboard_filler_nicknames.json`. Он нужен для воспроизводимой генерации SQL, а не для загрузки из игры.

Проверка соответствия JSON и миграции:

```bash
python3 tools/build_leaderboard_fillers.py --check
```

Генератор без --check создаёт 007 из JSON и неизменяемой миграции 006. Не переставляйте утверждённые слоты: порядок задаёт ID. После выпуска изменения оформляйте следующей миграцией; не переписывайте уже развёрнутую историю.

## Протокол

Обе функции принимают `(p_stars bigint = null, p_include_top boolean = true, p_language text = 'en')`. Старая двухаргументная сигнатура удаляется, чтобы PostgREST не видел неоднозначных перегрузок. Вызовы с двумя SQL-аргументами продолжают разрешаться через значение языка по умолчанию. Для нового клиента миграция 007 обязательна.

Строка заполнителя:

```json
{"player_id":"filler:cis:001","nickname":"Павел","stars":0,"rank":2,"is_me":false,"is_filler":true}
```

Строки реальных участников содержат `is_filler=false`. `me` никогда не указывает на заполнителя. При `p_include_top=false` заполнители не передаются: возвращаются подтверждение, собственная строка, реальное `total_players` и язык.

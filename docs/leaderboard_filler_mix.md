## Установка

В Supabase SQL Editor выполните только **`supabase/migrations/008_leaderboard_filler_mix.sql`**, если 005–007 уже применены. Новая миграция содержит все обновлённые имена и обе функции dev/production. Не запускайте 007 после 008: старая миграция возвращает старые правила выбора и имена.

Существующие реальные результаты, аккаунты, ID и расчёт «Топ N%» сохраняются. В таблицах fillers добавляется `style` (`casual` / `slang`), обновляются ровно 20 имён каждого пула. В каждом исходном пуле остаются **80 казуальных + 20 молодёжных** ников. Слоты и ID не перенумеровываются.

Примеры новых имён: «КринжовыйКабачок», «ЗумерНаЧиле», «ПлюсуюМолча», «КофеИПрокрастинация», CertifiedYapper, JustHereToLurk, NoContextNoodle, AverageCommentEnjoyer. Киберспортивных отсылок нет.

## Пропорции

Пропорции применяются только к заполнителям, а не ко всем строкам с реальными игроками:

| Язык интерфейса | СНГ | США/Европа |
|---|---:|---:|
| Русский | 60% | 40% |
| Английский | 20% | 80% |

Сначала определяется недостающее число строк: `N = max(0, 100 − число реальных строк в топе)`. Число СНГ-ников = округлённое до ближайшего целого `N × доля СНГ`; английских = `N − СНГ`. Это сохраняет ровно 100 строк. При малом N точные проценты невозможны: для 3 пустых мест получатся 2 СНГ + 1 английский в русском варианте, 1 СНГ + 2 английских в английском. Для 10 мест — 6+4 и 2+8 соответственно. Для пустого топа — ровно 60+40 и 20+80.

20 молодёжных ников — состав каждого исходного пула из 100; при случайной выборке конкретная доля молодёжных ников может отличаться от 20%.

## Случайный, но стабильный выбор

SQL выбирает нужное число уникальных имён без повторов из каждой группы по псевдослучайному порядку, вычисленному из UUID текущего аккаунта, группы и слота. Затем выбранные группы перемешиваются между собой вторым стабильным порядком. Региональные имена не идут отдельными блоками.

- Повторная загрузка и обновление JWT одного аккаунта не меняют подборку.
- Другой аккаунт получает другую подборку.
- При росте реального топа квоты заполнителей уменьшаются; из каждой группы исключается конец её выбранной последовательности. Порядок оставшихся имён относительно друг друга сохраняется.
- После создания нового анонимного аккаунта при отзыве сессии подборка может измениться вместе с идентификатором аккаунта.
- Смена языка меняет пропорции, а не сам рейтинг реальных участников.
- Заполнители по-прежнему идут ниже всех реальных игроков, имеют 0 звёзд и не участвуют в `total_players`, местах и процентах.

Новой постоянной очереди, записей на каждого игрока или отдельных аккаунтов для заполнителей не создаётся. Достаточно 200 строк fillers на окружение. Случайный выбор выполняет сервер; клиент получает только текущие строки.

## Источники и проверка

Текущий пул: `supabase/seeds/leaderboard_filler_nicknames_v2.json`. Он содержит 200 имён, номера 20 slang-слотов каждой группы и правила процентов. Исходный JSON и генератор 007 сохранены для воспроизводимости старой миграции.

```bash
python3 tools/build_leaderboard_fillers.py --check
python3 tools/build_leaderboard_filler_mix.py --check
NODE_PATH=<node_modules с @electric-sql/pglite> node tools/tests/leaderboard_sql.cjs
python3 tools/run_content_tests.py --godot <Godot> --suite leaderboard
```

Генератор без --check создаёт 008. Проверяются 80/20 стилей в обеих группах и обоих окружениях, 200 уникальных ников, сохранение 80 прежних имён, обе пропорции, частичные списки и округление, стабильность и отсутствие повторов, различие между аккаунтами, отсутствие фиктивных аккаунтов, прежние места/проценты, права и повторяемость миграций.

Debug-лог теперь содержит фактическую смесь, например:

```text
[Leaderboard] Top received: rows=100 real=90 fillers=10 cis=6 english=4 total_players=90 language=ru
```

В release диагностического вывода нет. Файлы пула и SQL остаются исключёнными из экспорта игры.

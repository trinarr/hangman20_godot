# Статистика ответов викторины через Supabase

База изменений: `59958d7`. Реализация выключена до настройки облачного проекта.

## Подключение

1. Создать проект Supabase.
2. В Authentication → Sign In / Providers включить Anonymous Sign-Ins.
   Клиент использует анонимный вход без email/пароля. CAPTCHA в этой версии клиента
   не реализована: включение обязательной CAPTCHA потребует дополнительной интеграции.
3. В SQL Editor последовательно выполнить:
   - `supabase/migrations/001_quiz_statistics.sql`;
   - `supabase/migrations/002_quiz_catalog.sql`.
4. В настройках Godot задать:

   ```ini
   [quiz_statistics]
   enabled=true
   supabase_url="https://PROJECT.supabase.co"
   publishable_key="sb_publishable_..."
   minimum_answers=30
   ```

   Допустим также legacy `anon` key. Использовать только публичный ключ.
   `service_role`, `sb_secret_...` и пароль базы в приложение не добавлять.
5. Экспортировать Android как обычно: разрешение INTERNET уже включено.

Для проверки отображения можно временно поставить `minimum_answers=1` и ответить
на вопрос. Никакие тестовые голоса в облако автоматически не добавляются.

## Поведение

- После ответа появляются проценты справа и небольшие анимированные полосы внизу
  кнопок. Зелёная/красная обратная связь и обычная кнопка продолжения сохраняются.
- До 30 голосов распределение скрыто. Порог настраивается.
- Варианты связываются с исходными индексами каталога, а не с порядком кнопок.
- RU и EN считаются отдельно. Редакция определяется SHA-256 текста вопроса,
  четырёх исходных вариантов и индекса правильного ответа. Исправление текста,
  порядка вариантов или правильного ответа создаёт отдельную статистику.
- Учитывается только первая попытка на одну редакцию вопроса для облачного аккаунта.
  Попытка с 50/50 отмечается пройденной, но не добавляет голос: последующие ответы
  на тот же вопрос также не увеличивают счётчики.
- Просмотр результата повторно не увеличивает счётчики. SQL-функция выполняет
  отметку попытки и прибавление счётчика в одной транзакции с блокировкой строки игрока.
- Статистика общая для всех уровней сложности. Это распределение среди игроков,
  которым действительно показали данный вопрос, а не оценка случайной аудитории.
- Игра не ждёт сеть. Очередь первых ответов и refresh token сохраняются отдельно
  от игрового прогресса в `user://quiz_statistics.json`. Повтор — каждые 30 секунд
  либо при следующем ответе. Очередь ограничена 4000 уникальными редакциями;
  при переполнении новый ответ не отправляется. Результаты кэшируются на время запуска.
- Неизвестные серверу редакции сохраняются до обновления каталога, не блокируя другие.
- Без настройки сервиса запросов нет. При сетевой ошибке обычная викторина работает.
- После удаления данных приложения/переустановки анонимная идентичность может потеряться.
  Восстановление и привязка аккаунта пока не реализованы. Невалидный refresh token
  не заменяется новой идентичностью автоматически: потребуется восстановление сессии.

## Хранение и обновление вопросов

В текущем проекте 1900 вопросов RU и 1900 EN. Для 3800 редакций отметки занимают
475 байт на игрока при полном заполнении обеих языковых версий. Профиль Supabase
Auth, строки, индексы и служебные данные занимают дополнительное место: это не
полный размер данных игрока и не гарантия вместимости тарифа.

После изменения вопросов выполнить:

```bash
python tools/build_quiz_statistics_catalog.py
```

Затем выполнить обновлённый `002_quiz_catalog.sql` в SQL Editor **до выпуска APK**.
Повторное выполнение не сбрасывает счётчики и не меняет позиции старых редакций.
Нельзя очищать/пересоздавать каталог, перенумеровывать `slot` или удалять строки
ради повторного использования их позиций: отметки игроков привязаны к этим позициям.
SQL-файл для существующего проекта применяется как добавление, а не сброс базы.

## Границы первой версии

Прямой доступ клиентов к таблицам закрыт; публично доступна только функция
`quiz_answer` для роли `authenticated`. Каталог находится в закрытой схеме.
Это защищает от перезаписи счётчиков и повторного учёта на одном аккаунте,
но не от поддельных ответов и массового создания анонимных аккаунтов.
Лидерборды и полноценная защита от накрутки в этот патч не входят.

## Проверки

```bash
python tools/run_content_tests.py --godot /path/to/godot --suite quiz_statistics
python tools/run_content_tests.py --godot /path/to/godot --suite bonus_quiz
```

Первая проверка сверяет весь каталог RU/EN с SQL, перестановки вариантов,
восстановление вопросов, повторы, обновление токена, офлайн-очередь, пропуск
неизвестных редакций и виджеты результата. Изолированное сохранение создаёт runner.

SQL можно проверить локально в PostgreSQL WASM без проекта Supabase:

```bash
npm install --prefix /tmp/hangman-sql @electric-sql/pglite
NODE_PATH=/tmp/hangman-sql/node_modules node tools/tests/quiz_statistics_sql.cjs
```

Тест использует временную базу в памяти, имитирует роли и `auth.uid()` и проверяет
миграции, разрешения, первые/повторные голоса и рост битовых отметок.
Сквозная проверка с живым Supabase выполняется после настройки проекта.

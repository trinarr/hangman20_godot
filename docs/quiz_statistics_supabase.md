# Статистика ответов викторины через Supabase

База изменений: `59958d7`. Реализация выключена до настройки облачного проекта.

## Подключение

1. Создать проект Supabase.
2. В Authentication → Sign In / Providers включить Anonymous Sign-Ins.
   Клиент использует анонимный вход без email/пароля. CAPTCHA в этой версии клиента
   не реализована: включение обязательной CAPTCHA потребует дополнительной интеграции.
3. В SQL Editor последовательно выполнить:
   - `supabase/migrations/001_quiz_statistics.sql`;
   - `supabase/migrations/002_quiz_catalog.sql`;
   - `supabase/migrations/003_quiz_statistics_prefetch.sql`.
4. В настройках Godot задать:

   ```ini
   [quiz_statistics]
   enabled=true
   supabase_url="https://PROJECT.supabase.co"
   publishable_key="sb_publishable_..."
   minimum_answers=30
   ```

   Допустим также legacy `anon` key. Использовать только публичный ключ.
   `service_role`, `sb_secret_...` и пароль базы в приложение не добавлять.
5. Экспортировать Android как обычно: разрешение INTERNET уже включено.

Для проверки отображения можно временно поставить `minimum_answers=1` и ответить
на вопрос. Никакие тестовые голоса в облако автоматически не добавляются.

## Обновление уже подключённого проекта

Перед запуском обновлённой игры выполнить только `003_quiz_statistics_prefetch.sql`
в SQL Editor. Пересоздавать таблицы и запускать каталог заново не требуется;
голоса и отметки первых попыток сохраняются. Миграция заменяет функцию транзакционно,
без неоднозначных перегрузок. Старые клиенты с двумя параметрами продолжают получать
счётчики, поскольку новый третий параметр имеет значение по умолчанию `true`.

## Предварительная загрузка и отправка

- При показе этапа, переходе к следующему вопросу и замене вопроса игра заранее
  вызывает `quiz_answer(p_key, -1, true)`. Один ответ содержит `ok`, четыре `counts`
  и `already_answered`. Чтение не создаёт отметку попытки и не увеличивает счётчики.
- До выбора статистика остаётся в памяти. После выбора первая попытка без 50/50
  локально прибавляется к кэшу, и заливка появляется сразу. Повторная попытка и
  попытка с 50/50 счётчики не увеличивают. Для офлайн-очереди используется её первый ответ.
- Если кэш готов, отправляется голос с `p_include_counts=false`; ответ — только
  `{"ok":true}`. После подтверждения запись удаляется из очереди. Без подтверждения
  повторная отправка сохраняет защиту от двойного учёта.
- Если кэш не получен, голос отправляется с `p_include_counts=true`: сервер возвращает
  счётчики уже с учтённым голосом и отметку попытки. Повторно голос локально не добавляется.
- Ответ во время предварительного запроса учитывается один раз после получения
  снимка. Авторизация, предварительные запросы и отправка сериализованы.
- При отсутствии связи обычный результат показывается сразу. Кэш действует на время
  запуска; предварительная загрузка повторяется каждые 30 секунд при ошибках.
  Это снимок статистики, а не непрерывное обновление: голоса других игроков после
  загрузки будут видны при следующей загрузке вопроса.

## Подсказка 50/50

При нажатии используется уже загруженная статистика текущей редакции вопроса.
Если сумма голосов **строго больше** `minimum_answers`, убираются два наименее
популярных неправильных варианта. Правильный ответ всегда сохраняется, даже
если он менее популярен. При равном числе голосов выбор между вариантами случайный.
Если данных ещё нет или сумма голосов меньше либо равна порогу, сохраняется
обычный случайный выбор двух неправильных ответов. Дополнительного запроса
и ожидания сети при нажатии нет. Стоимость и анимация подсказки не меняются.
В debug-логах `[QuizStatistics] 50/50` указан применённый способ выбора.

## Диагностика в debug-сборке

Обращения к Supabase в debug-сборках и редакторе отключены независимо от
`quiz_statistics/enabled`. Очередь не отправляется, а таймер повторов не запускается.
Действуют также запреты в проверке конфигурации и непосредственно перед созданием
HTTP-запроса. Проверять реальное облако теперь нужно release-сборкой.
Тесты используют mock без HTTP; runner дополнительно задаёт
`HANGMAN_SUPABASE_NETWORK_DISABLED=1`, чтобы запретить транспорт и при запуске
через исполняемый файл без признака debug. Существующая очередь сохраняется.

Сообщения с префиксом `[QuizStatistics]` доступны в Godot Output, Android Logcat
и встроенной debug-консоли (четыре быстрых нажатия в правом верхнем углу).
В release-сборке эти сообщения не выводятся.

- `Startup: configured=true` — URL, публичный ключ и включение фичи заданы.
  При `enabled=false` сначала включить `quiz_statistics/enabled` в `project.godot`.
- `Auth complete: access_token_present=true` — сессия получена.
- `Prefetch ready` — заранее получены счётчики и отметка попытки.
- `Local first attempt applied` — первая попытка добавлена к локальному снимку.
- `Submit: include_counts=false` → `Database acknowledged` — голос принят без
  повторной загрузки счётчиков; при `true` сервер также возвращает распределение.
- `UI: displaying distribution` — данные переданы на экран результата;
  `UI: hidden` показывает количество голосов и порог отображения.
- Сетевые ошибки, HTTP-коды, коды ошибок сервера и размер очереди помогают
  отличить отсутствие связи от проблемы авторизации или каталога.

Ключи, токены, ID аккаунта и полные тела ответов авторизации не выводятся.

## Поведение

- После ответа плавно заполняется фон кнопок на всю высоту, без числовых процентов.
  Визуальная ширина ограничена диапазоном 8–92%, чтобы нулевые варианты были видны,
  а максимальный оставлял незаполненный участок. Счётчики на сервере не меняются. Анимация длится 0,8 секунды.
  Цвета и текст восстановлены из версии 4.0.1: обычный фон #FFFFFF,
  правильный #56D782, неправильный #F45B77; текст #121A52 без дополнительного эффекта.
  Заливка статистики — соответствующий фон, затемнённый на 12% (`darkened(0.12)`).
  Зелёная/красная обратная связь и обычная кнопка продолжения сохраняются.
- До 30 голосов распределение скрыто. Порог настраивается.
- Варианты связываются с исходными индексами каталога, а не с порядком кнопок.
- RU и EN считаются отдельно. Редакция определяется SHA-256 текста вопроса,
  четырёх исходных вариантов и индекса правильного ответа. Исправление текста,
  порядка вариантов или правильного ответа создаёт отдельную статистику.
- Учитывается только первая попытка на одну редакцию вопроса для облачного аккаунта.
  Попытка с 50/50 отмечается пройденной, но не добавляет голос: последующие ответы
  на тот же вопрос также не увеличивают счётчики.
- Просмотр результата повторно не увеличивает счётчики. SQL-функция выполняет
  отметку попытки и прибавление счётчика в одной транзакции с блокировкой строки игрока.
- Статистика общая для всех уровней сложности. Это распределение среди игроков,
  которым действительно показали данный вопрос, а не оценка случайной аудитории.
- Игра не ждёт сеть. Очередь первых ответов и refresh token сохраняются отдельно
  от игрового прогресса в `user://quiz_statistics.json`. Повтор — каждые 30 секунд
  либо при следующем ответе. Очередь ограничена 4000 уникальными редакциями;
  при переполнении новый ответ не отправляется. Результаты кэшируются на время запуска.
- Неизвестные серверу редакции сохраняются до обновления каталога, не блокируя другие.
- Без настройки сервиса запросов нет. При сетевой ошибке обычная викторина работает.
- После удаления данных приложения/переустановки анонимная идентичность может потеряться.
  Восстановление и привязка аккаунта пока не реализованы. Невалидный refresh token
  не заменяется новой идентичностью автоматически: потребуется восстановление сессии.

## Хранение и обновление вопросов

В текущем проекте 1900 вопросов RU и 1900 EN. Для 3800 редакций отметки занимают
475 байт на игрока при полном заполнении обеих языковых версий. Профиль Supabase
Auth, строки, индексы и служебные данные занимают дополнительное место: это не
полный размер данных игрока и не гарантия вместимости тарифа.

После изменения вопросов выполнить:

```bash
python tools/build_quiz_statistics_catalog.py
```

Затем выполнить обновлённый `002_quiz_catalog.sql` в SQL Editor **до выпуска APK**.
Повторное выполнение не сбрасывает счётчики и не меняет позиции старых редакций.
Нельзя очищать/пересоздавать каталог, перенумеровывать `slot` или удалять строки
ради повторного использования их позиций: отметки игроков привязаны к этим позициям.
SQL-файл для существующего проекта применяется как добавление, а не сброс базы.

## Границы первой версии

Прямой доступ клиентов к таблицам закрыт; публично доступна только функция
`quiz_answer` для роли `authenticated`. Каталог находится в закрытой схеме.
Это защищает от перезаписи счётчиков и повторного учёта на одном аккаунте,
но не от поддельных ответов и массового создания анонимных аккаунтов.
Лидерборды и полноценная защита от накрутки в этот патч не входят.

## Проверки

```bash
python tools/run_content_tests.py --godot /path/to/godot --suite quiz_statistics
python tools/run_content_tests.py --godot /path/to/godot --suite bonus_quiz
```

Первая проверка сверяет весь каталог RU/EN с SQL, перестановки вариантов,
восстановление вопросов, повторы, обновление токена, офлайн-очередь, пропуск
неизвестных редакций и виджеты результата. Изолированное сохранение создаёт runner.

SQL можно проверить локально в PostgreSQL WASM без проекта Supabase:

```bash
npm install --prefix /tmp/hangman-sql @electric-sql/pglite
NODE_PATH=/tmp/hangman-sql/node_modules node tools/tests/quiz_statistics_sql.cjs
```

Тест использует временную базу в памяти, имитирует роли и `auth.uid()` и проверяет
миграции, разрешения, первые/повторные голоса и рост битовых отметок.
Новый протокол проверен локально на PostgreSQL; проверка с живым Supabase требует
выполнения миграции 003 в подключённом проекте.

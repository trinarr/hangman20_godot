# Обновление сессии статистики

Изменения поверх `0d50a32`. SQL и настройки Supabase менять не требуется.
Этот документ заменяет прежнее описание поведения при невалидном refresh token
в `quiz_statistics_supabase.md`.

## Обычное истечение JWT

Клиент использует `expires_in` из ответа авторизации и монотонные часы Godot.
Перед запросом обновляет сессию заранее, обычно за 30 секунд до истечения JWT
(для короткого срока — за 10% его длительности). При отсутствии `expires_in`
остаётся обработка HTTP 401.

Если сервер отклонил RPC с HTTP 401, игра сразу обновляет сессию через refresh token
и повторяет исходный запрос один раз. Таймер 30 секунд для этого не ожидается.
Второй HTTP 401 останавливает немедленный повтор, чтобы не создавать цикл запросов.
Очередь удаляется только после подтверждённого ответа RPC. Повтор голоса остаётся
безопасным благодаря серверной дедупликации для прежнего аккаунта.

Авторизация и RPC по-прежнему выполняются одним worker последовательно.

## Отозванная или потерянная сессия

При подтверждённой окончательной ошибке refresh игра автоматически:

1. Очищает старые токены, очередь неотправленных/неподтверждённых ответов, кэш
   статистики и индивидуальные отметки попыток в памяти.
2. Сохраняет очищенное состояние.
3. Создаёт новый анонимный аккаунт и сохраняет новую пару токенов.

Старая очередь не отправляется под новым ID, в том числе если отзыв обнаружен
во время отправки одного из её ответов. Предварительное чтение можно безопасно
повторить под новым аккаунтом. Новый ответ, добавленный уже после сброса личности,
сохраняется и обрабатывается под новым аккаунтом.

Общие счётчики на сервере и прежний серверный аккаунт не удаляются. Их голоса
не вычитаются. Игра продолжает работу с новой идентичностью и новой историей
первых попыток, поэтому ранее пройденные вопросы для неё снова могут быть первыми.
Неподтверждённые ответы старой очереди при таком сбросе теряются намеренно.

Обрабатываются коды `refresh_token_not_found`, `refresh_token_already_used`,
`session_not_found`, `session_expired`, `user_not_found` и legacy `invalid_grant`
в ошибке refresh с HTTP 400/401/403. Неизвестные ошибки, HTTP 429, сетевые ошибки,
HTTP 5xx и блокировка аккаунта не приводят к созданию новой личности или удалению очереди.

Если регистрация нового аккаунта не удалась, старая очередь не восстанавливается;
создание нового аккаунта повторяется позднее. Само прохождение игры от сети не зависит.

## Диагностика и тесты

Логи `[QuizStatistics]` отмечают обновление JWT, ограниченный немедленный повтор
и сброс отозванной сессии. Токены не выводятся.

Сохранён запрет реального Supabase для debug/editor и тестового runner из `0d50a32`.
Проверки сессии используют mock без HTTP:

```bash
python tools/run_content_tests.py --godot /path/to/godot --suite quiz_sessions
python tools/run_content_tests.py --godot /path/to/godot --suite quiz_statistics
```

## Срок жизни

По умолчанию сессии Supabase бессрочные. Access token обычно истекает через час,
но это штатное обновление токенов, а не отзыв сессии. Сессию можно завершить
административным действием; также возможны истечение по настроенным ограничениям
и срабатывание защиты от недопустимого повторного использования refresh token.
Клиент обнаруживает такой отзыв при очередном обновлении сессии.

Официальные источники: [сессии](https://supabase.com/docs/guides/auth/sessions),
[коды ошибок](https://supabase.com/docs/guides/auth/debugging/error-codes).

# Правила работы агентов

## Начало работы

- Работай из корня рядом с `project.godot`. Сначала проверь `git status --short`; сохраняй чужие изменения и ограничивай diff текущей задачей.
- Точка входа в текущую документацию — [README.md](README.md); проверки — [tools/TESTS.md](tools/TESTS.md), сборка Android — [tools/EXPORT.md](tools/EXPORT.md). При изменении этих процессов обновляй соответствующую инструкцию; не дублируй таблицы баланса и каталога вне их источников.
- Ищи нужные символы через `rg`, затем читай соответствующие функции и их потребителей. Не загружай целиком `main_portrait.gd` без необходимости.
- Текущее поведение определяют код, данные и проверки. История патчей и закрытых задач хранится в Git; не создавай её дубликаты в отдельных отчётах. Причины действующих ограничений сохраняй в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), открытые проблемы — в аудите.
- Общайся с пользователем по-русски. Следуй языку и оформлению окружающего кода; не переводи существующие идентификаторы и комментарии массово.
- Завершай задачу конкретным результатом: изменённые файлы, выполненные проверки, оставшиеся ограничения. Не называй непроведённую проверку успешной.

## Карта проекта

- Godot 4.x; `project.godot` объявляет features `4.7`, renderer `mobile`, портретный viewport 960×1600, `canvas_items` / `expand`.
- Вход: `scenes/Main.tscn` → `scripts/main_portrait.gd` → наследование `scripts/main.gd`. Почти весь интерфейс создаётся кодом; одной правки сцены обычно недостаточно.
- `scripts/core/`: состояние, сохранения, игровой сеанс, подбор контента, турнир, конфигурация. Порядок autoload в `project.godot` — часть зависимостей запуска.
- `scripts/ui/`: компоненты интерфейса. `ui_palette.gd`, `ui_fonts.gd`, `ui_materials.gd` — общие цвета, шрифты и материалы.
- `scripts/services/`: согласие по региону, статистика викторины и лидерборд. `addons/GodotAndroidYandexAds/` включает обёртку, Java-исходник и готовые AAR; изменение Java само по себе не обновляет AAR.
- `data/`: баланс, редакторские каталоги и игровые JSON; `localization/translations.csv` — исходник перевода UI.
- `flash_assets/`, `assets/profile/`, `assets/app_icon/` — графика; `symbols/` и `img/` — импортированные анимации персонажей; `shaders/` — эффекты.
- `tools/` — валидаторы, генераторы данных и тесты; `supabase/migrations/` — последовательные SQL-миграции. Обзор аудита: [docs/PROJECT_AUDIT.md](docs/PROJECT_AUDIT.md).

## Изменения кода и поведения

- Используй GDScript 4, табуляцию и явные типы там, где они приняты в соседнем коде. Не проводи массовое форматирование.
- Новую самостоятельную UI-логику помещай в существующий подходящий компонент либо выделяй небольшой компонент в `scripts/ui/`. Не увеличивай главные скрипты новыми независимыми подсистемами. Не совмещай локальное исправление с глобальным разбиением этих файлов.
- Баланс, цены, награды, таймеры и сложность меняй через `data/game_design_config.json` и `GameDesignConfig`. Не дублируй настройки числовыми константами в экранах.
- Цвета и шрифтовые профили бери из общих UI-модулей. Переиспользуй существующие кнопки, popup, адаптивную раскладку и эффекты.
- Не меняй общий изменяемый `ShaderMaterial` для независимых анимаций: проверь его владельцев и при необходимости создай отдельный экземпляр.
- Узел должен владеть своими tween, сигналами, таймерами и deferred-callback. При закрытии/повторном открытии проверяй отмену старой анимации и жизнеспособность адресата callback.
- Декоративные `Control` не должны перехватывать ввод (`MOUSE_FILTER_IGNORE`); сохраняй пропорции иконок.
- Сохраняй штатный путь загрузки импортируемых ресурсов через `load` / `preload` / `ResourceLoader`. Не читай PNG из `res://` через сырой файловый API: экспорт использует remap.
- Не меняй Android package ID, порядок autoload, renderer, ориентацию и экспортные фильтры попутно с несвязанной задачей.

## Сохранения, награды и сеть

- Сохранения принадлежат `GameState`: primary `.json`, временный `.tmp`, резервный `.bak`, версия формата и миграции. Не обходи этот механизм записью из UI.
- Сохраняй числовые значения опубликованных enum, постоянные ID контента, reserved-поля и поддержку продолжения партии. Удаление совместимости требует явного решения в рамках задачи.
- При изменении формата добавляй последовательную миграцию; сохраняй защиту от перезаписи сохранения более новой версии и восстановление после прерванной записи.
- Начисление награды должно оставаться идемпотентным и независимым от анимации. Проверяй повторные/поздние рекламные сигналы, перестановку rewarded/closed, перезапуск и лимит баланса.
- Не запускай тестовые сцены на реальном `user://` игрока. `XDG_DATA_HOME` из Linux-примеров не обеспечивает изоляцию на Windows.
- Для поддерживающих этот флаг сетевых тестов используй `HANGMAN_SUPABASE_NETWORK_DISABLED=1`; отдельно проверяй, что выбранный путь действительно читает флаг.
- Не выполняй SQL в подключённой базе и не меняй боевые рекламные настройки в ходе локальной проверки. Новые изменения БД оформляй следующей миграцией, учитывай dev/prod RPC, права и RLS.
- Не добавляй серверные секреты, service-role ключи, токены сессий и ключи подписи в клиент/логи. Клиентский publishable key сам по себе не доказывает утечку секрета; безопасность RPC проверяется отдельно.

## Контент и графика

- Слова редактируй в `data/word_catalog_ru.json` / `word_catalog_en.json`; runtime `words_*` / `hints_*` генерирует `tools/curate_word_database.py`. Без `--check` он записывает файлы.
- Викторина: `data/quiz_catalog.json` → `quiz_questions_*` / `quiz_explanations_*`; `tools/verify_quiz_catalog.py --write` записывает runtime. Без `--write` это проверка.
- Сохраняй ID, соответствие слов и подсказок, тему, правила сложности и миграционные связи. RU/EN — самостоятельные базы, их записи не обязаны быть дословными переводами.
- Меняя UI-текст, проверь оба языка и импорт `translations.csv`; не редактируй бинарные `.translation` вручную.
- Перед генерацией или заменой иконок обязательно прочитай [docs/ICON_GUIDELINES.md](docs/ICON_GUIDELINES.md), открой реальные референсы и найди место использования.
- Не перерисовывай персонажей и не переименовывай импортированные кадры `img/` / сцены `symbols/` в рамках оптимизации. Сохраняй защищённые ресурсы El Tigre, включая отдельный портрет.
- Не удаляй графику только по поиску имени: проверь сцены, preload, динамические пути, launcher и `tools/audit_texture_usage.py`.
- `tools/upscale_art_2x.py` и `tools/refine_ui_icons.py` изменяют оригиналы. Не запускай их повторно для «улучшения». Сначала проверяй манифест; его обновление допустимо после проверки намеренного изменения, а не для маскировки ошибки.
- Сохраняй отслеживаемые `.uid` и `.import`; не коммить `.godot/`, временные профили, экспортные сборки и локальные секреты. Новые import-метаданные получай через Godot.

## Проверки по затронутой области

Команды ниже выполняются из корня. `python` означает доступный Python 3. Инструменты явно читают/пишут UTF-8; установка `PYTHONUTF8` для проверки JSON не требуется:

```powershell
python tools/verify_game_design_config.py
python tools/verify_optimization.py
```

| Изменение | Дополнительные проверки |
| --- | --- |
| Слова / подсказки | `python tools/curate_word_database.py --check`, `python tools/verify_word_catalog.py`, `python tools/verify_word_content_migration.py`, `python tools/verify_theme_catalog.py` |
| Викторина | `python tools/verify_quiz_catalog.py`, `python tools/verify_quiz_answer_leaks.py`, `python -m unittest discover -s tools/tests -p test_quiz_editorial.py` |
| Сохранения / награды / реклама | `python tools/verify_save_integrity.py`, соответствующие Godot suites `rewards`, `save_recovery`, `resume_flow`, `runtime_optimizations`; для обёртки согласия `run_ad_consent_tests.py` |
| Текстуры / иконки | `python tools/audit_texture_usage.py`, `python tools/upscale_art_2x.py --verify`, визуальное сравнение в целевом UI |
| UI / шрифты / шейдеры | Подходящий сценарий из `tools/tests/*render*`, проверка на GPU и обоих языках; headless не подтверждает внешний вид |

- Сначала посмотри `--help` и актуальные suites в запускателе. `run_content_tests.py` и `run_reward_tests.py` поддерживают Windows и Linux через `tools/godot_test_runner.py`. До запуска игровых autoload проверяется реальный путь `user://`; окружение процесса направляется во временный профиль, сеть Supabase отключена. Не обходи эту проверку прямым запуском `.tscn`.
- Для Windows: `python tools/run_content_tests.py --godot 'C:/path/to/Godot.exe' --suite <name>`; награды: `python tools/run_reward_tests.py --godot 'C:/path/to/Godot.exe' --suite rewards`. На Linux укажи путь к Linux-бинарнику теми же параметрами. Целевая платформа игры остаётся Android.
- Регрессии инструментов: `python -m unittest discover -s tools/tests -p test_project_tools.py`. Для проверки изоляции настоящим движком задай `HANGMAN_TEST_GODOT` с путём к бинарнику; без него этот сценарий пропускается. Запускатели отказываются работать при локальном `override.cfg`, пока его влияние на сохранения не проверено.
- Перед Godot suites выполни импорт ресурсов выбранным движком. Проверяй exit code, итоговый отчёт и отсутствие `ERROR` / `SCRIPT ERROR`; предупреждения об утечках фиксируй отдельно.
- Текущие известные ошибки инструментов и ограничения перечислены в аудите. Не объявляй весь проект зелёным из-за успешного поднабора проверок; не переписывай тесты под реализацию ради зелёного результата.
- UI проверяй при 960×1600 и 690×1536, включая повторное открытие/закрытие, быстрые нажатия и завершение анимации после ухода с экрана. При изменении адаптации проверь ещё одно соотношение сторон.
- Для документационной задачи достаточно проверки ссылок и diff; новые игровые тесты без изменения поведения не нужны.
